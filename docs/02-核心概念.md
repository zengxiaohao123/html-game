# 02 · 核心概念

> 本文档定义整套游戏的**基础词汇表**。术语之间若存在冲突，以本文档为准。所有面向玩家的 UI 文字必须遵循本文档的术语。

---

## 一、地块相关

### 1.1 地块（Cell）

地图由格子组成，每一格称为一个**地块**。代码里 `G.map.cells[y*n+x]` 是地块数组。

一个地块的核心字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `terrain` | 字符串 | 地形大类。只有 `void` 是不可通行、不可附着、不受效果影响。其他地形细分由设计者定义 |
| `content` | `null \| { type, sub?, done? }` | 地块内容（探索时显示的图标）：`battle` / `emergency` / `event` / `loot` / `empty` / `reward` |
| `attach` | `null \| 'fire' \| 'water' \| 'grass' \| 'thunder' \| 'ice' \| 'wind' \| 'rock'` | 元素附着（仅地块上有，实体上没有）。null 表示无元素附着 |
| `entities` | `Entity[]` | **该地块上的实体列表，可叠放无限多个**。UI 每 2 秒循环切换显示每个实体的图标 |
| `isEnemySpawnPoint?` | `boolean` | **战斗态专用**：标记这一格是敌人进攻点（不是实体，被占据不影响生成）。默认为 false |

### 1.2 地块的严谨分类（四种叠加概念）

**这四种分类是独立正交的**，一个地块可以同时满足多个：

| 分类 | 判定 | 说明 |
|---|---|---|
| **空地块** | `entities.length === 0 && attach === null` | 严谨术语，只在战斗里出现；意思是"无实体 + 无元素附着" |
| **元素地块** | `attach !== null` | 有元素附着的地块，不管有没有实体 |
| **实体地块** | `entities.length > 0` | 有实体的地块（可多个），不管有没有元素附着 |
| **元素实体地块** | `entities.length > 0 && attach !== null` | 同时有实体和元素附着 |

**外部地块**（`terrain === 'void'`）：地图最外圈。**不可进入、不可移动、不可被施加附着、不可受任何效果影响**。索敌范围计算必须自动跳过外部地块。

### 1.3 地块内容（`content.type`）

| 类型 | 探索里的意义 | 战斗开始时 | 战斗结束时 | 玩家进入过后 |
|---|---|---|---|---|
| `battle` 作战 | 进入触发战斗 | 隐藏内容，内容**暂时失效** | 恢复（若玩家未进过） | 玩家进过一次后 → `content.type` 自动改为 `empty` |
| `emergency` 紧急作战 | 进入触发较难的战斗 | 同上 | 同上 | 同上 |
| `event` 事件 | 进入触发剧情对话 | 同上 | 同上 | 事件结束后 → `type` 改为 `empty` + `done:true` |
| `loot` 奖励 / 战利品 | 进入触发拾取界面 | 同上 | 同上 | 拾取后 → `type` 改为 `empty` + `done:true` |
| `empty` 空地 | 进入触发空地搜索（消耗 1 行动力） | — | — | — |
| `reward` 奖励（boss 战） | 进入触发 Boss 战斗 | 同上 | 同上 | 同上 |
| `external` 外部地块 | 永远不可通行 | — | — | — |

### 1.4 元素附着（核心重做点）

**附着对象：地块，不是实体。实体本身没有"附着"字段，不会被附着。**

七条硬规则：

1. **一个地块至多有一层附着**。施加第二层时立即进入"元素反应"流程
2. 地块上的实体如何移动 → 不影响该地块的附着（实体走了附着还在）
3. **七种元素全部可以附着**：火、水、草、雷、冰、风、岩（旧代码曾把风岩排除在外，**已删除**）
4. 附着**只能在战斗中施加**，探索里无法主动施加
5. 战斗结束时附着**不会被清除**（元素反应/召唤物可能刚留下附着）
6. 下一日生成新地图时**统一清除全部附着**（新地图 → 新初始状态）
7. 极少数地块会被特殊说明"不允许施加附着"（默认所有非外部地块都允许）

### 1.5 附着 vs 伤害的区别（精确术语）

| 术语 | 含义 | 例子 |
|---|---|---|
| **X 属性伤害** | 造成该种元素的伤害**但不施加附着** | "对前方造成火属性伤害" → 不触发反应，只走抗性计算 |
| **X 元素伤害** | 先施加 X 附着，再造成 X 属性伤害。若附着引发反应 → 先结算反应 → 再结算属性伤害 | "对前方造成火元素伤害" → 先 `attach='fire'`，可能触发蒸发/燃烧等，反应完再走伤害 |
| **范围 X 元素伤害** | 统一对范围内**所有符合条件的地块**施加附着，再统一对范围内**所有符合条件的单位**造成属性伤害 | 夏阳「燎原·连携」：先给前方所有地块打火附着（可能连锁反应），再给范围内所有敌人打火属性伤害 |

## 二、实体相关

### 2.1 实体（Entity）

战斗和探索中，每一个独立的"能动的东西"就是一个实体。**每个地块内至多 1 个实体**。

### 2.2 实体的阵营（faction）

| 阵营 | 子分类 | 说明 |
|---|---|---|
| **我方** | 主角（pro）、队友（xiayang / luyouyou …）、我方召唤物 | 我方召唤物永远属于召唤它的玩家所在阵营 |
| **敌方** | 普通敌人、敌方召唤物、Boss | — |
| **中立** | 野生史莱姆、流浪 NPC 等 | 是否可被我方/敌方攻击由该实体单独声明；默认双方都不会主动攻击 |

### 2.3 实体的行动约束

- **队友和主角位置 + 朝向永远绑定**：主角走到哪、队友跟到哪；主角朝向哪、队友朝向哪。**队友没有独立生命系统，不会死亡**，但**队友可以被硬控制**（被束缚时不能放主动/自动/连携技能，但朝向绑定仍生效）
- **队友是"技能 owner"但不是独立操作个体**：玩家放技能时操作技能组即可，不需要切换角色。每个技能数据里有明确的 owner（`charKey`），技能释放时行动节点、次数、冷却都记在 owner 头上。队友的行动节点**独立存在**，但队友没有主动操作，节点通常在自动技能释放前或硬控回合开始时触发
- **我方召唤物**：有独立的行动节点、独立的 AI、独立的技能。不占用技能组槽位
- **主角 / 敌方**：拥有速度属性（影响逃跑概率）；**队友 / 我方召唤物 / 敌方召唤物 / 中立**：没有速度属性

### 2.4 敌人进攻点（Enemy Spawn Point）

**战斗态专用的地块标记**，不是实体。每个战斗会有 1 个或多个敌人进攻点（默认 1 个，未来可多个）。

| 要点 | 说明 |
|---|---|
| 数据层 | 地块的 `isEnemySpawnPoint: true` 标记，或 `combatState.enemySpawnPoints: [{x,y}, ...]` 数组 |
| 是不是实体 | **不是实体**，不占实体槽位，不参与任何基于实体的逻辑（索敌、伤害、附着等都不认识它） |
| 被占据了怎么办 | **不影响生成**。进攻点格可以被主角、队友、我方召唤物、敌人占据；新敌人仍然会生成在进攻点坐标上（和其他实体叠在同一格） |
| 选格规则 | 战斗开始时，从所有 `terrain !== 'void'` 且当前未被标记的格子中随机选一个 |

每回合开始时，从所有敌人进攻点生成本回合的敌人（默认每个进攻点生成 1 个，特殊说明时可一次生成多个）。

### 2.5 碰撞伤害

**默认且所有敌人都有**，不会在各敌人描述里重复。

> 敌人在移动后，经过了或者恰好停留在主角所在地块时，造成相当于敌人**攻击力 100% 的物理伤害**。每个敌人每回合限 1 次。

精确语义见 [03-战斗系统 §四](03-战斗系统.md)。核心边界：
- 敌人**移动前已在主角格原地不动** → 不触发（必须有移动行为）
- **经过**每一步都算 + **最终停留**也算，但每敌人每回合**总共只触发 1 次**
- 主角和敌人堆叠在同一格但本回合都没移动 → **不会反复触发**（没移动就没触发前提）
- 无特殊说明的伤害一律可被护盾抵挡，碰撞伤害也一样

## 三、元素相关

### 3.1 七种元素

火（fire）、水（water）、草（grass）、雷（thunder）、冰（ice）、风（wind）、岩（rock）。

### 3.2 元素抗性

**每种元素有独立的抗性值**，物理抗性也属于元素抗性。

| 抗性 | 说明 |
|---|---|
| 计算过程 | `最终伤害 × (1 - 抗性%)` |
| 上下限约束 | 计算过程可以超出范围，但**最终必须 clamp 到 `-100% ~ +90%`** |
| 负值含义 | 受到的该种伤害**增加**（比如 -50% 抗性 = 受该种伤害时最终 +50%） |
| 未声明默认 | 所有元素抗性默认 0 |

### 3.3 伤害分类（用于索敌与元素反应判定）

| 分类 | 说明 |
|---|---|
| 元素伤害（elementalDamage） | 会施加元素附着、可能触发元素反应的伤害 |
| 属性伤害（attributeDamage） | 不施加附着、只走抗性计算的伤害。**物理伤害 = 属性伤害的特例** |
| 物理伤害 | 无元素、纯攻击力减防御的伤害。属于属性伤害子类，有物理抗性字段 |

## 四、技能相关

### 4.1 四种技能类型

| 类型 | 别名 | 作用时机 | 手动触发 | 放入技能组 | 触发节点 | 冷却 |
|---|---|---|---|---|---|---|
| **主动技能（active）** | — | 玩家操控阶段 | ✅ 必须手动点/快捷键 | ✅ 可放技能组 | 释放前触发 owner 行动节点 | 有（默认 1 回合） |
| **自动技能（auto）** | — | 自动技能阶段 | ❌ 玩家无法手动释放 | ✅ 可放技能组 | 释放前触发 owner 行动节点（保险） | 有 |
| **连携技能（link）** | 连携技 | 任意时刻，有 2 秒窗口时 | ✅ 按 E 键 | ✅ 可放技能组 | ❌ **不触发行动节点** | 有 |
| **天赋技能（talent）** | 天赋 | 编入编队时立即生效（全场景） | ❌ | ❌ 不占技能组 | — | 永久 |

**主动技能总数量硬上限：整个技能组里所有 active 技能的总和 ≤ 4**。这是规格数字，与初始 4 槽巧合重名但不是同一个约束。

### 4.2 技能组（SkillGroup）—— 全体系的核心

**技能组 = 整个编队共用的一套技能槽位**。不是每个角色各自一套。

#### 槽位生成规则

```
初始槽位：4 个
编队每有 1 个角色（主角自己算 1 人）→ 解锁 +1 槽位
槽位上限：min(10, 4 + teamSize)
```

#### 槽位里可以放什么

| 槽位位置 | 允许放 |
|---|---|
| 槽 1 ~ 槽 4（前 4 个） | 任意 kind：active / auto / link |
| 槽 5 起（额外解锁） | auto / link（**active 不允许放进槽 5+**，会被自动重排序挪回前面的 active 块） |

#### 自动重排序规则

**自动重排序只处理"大排序"，不打乱玩家手动在同类内部做的拖拽顺序：**

```
[ active 块（玩家手动拖拽后的内部顺序保持） ]
   ← 自动把所有 active 挪到这里
   ← 若 active 总数 > 4 → 拒绝新 active（校验时直接报错）
[ auto 块（玩家手动拖拽后的内部顺序保持） ]
   ← 自动把所有 auto 挪到这里
[ link 块（玩家手动拖拽后的内部顺序保持） ]
   ← 自动把所有 link 挪到这里
```

重排序后自动重新编号 slot（1, 2, 3, …）。

**触发自动重排序的时机**：每次向技能组里添加一个新技能、从技能组里卸下一个技能、切换编队人员。

**什么情况下会触发"禁止添加"**：
1. 槽位已满上限（`group.length >= min(10, 4 + teamSize)`）
2. 主动技能总数已达 4，再尝试加 active
3. 尝试加的技能 id 已经在技能组里了（重复）
4. 技能所属角色不在当前编队里

**二击切换交互**（**没有 ❌ 按钮，完全靠点击切换**）：
1. 点技能 tile 第 1 次 → 选中，右侧技能描述区显示该技能详情
2. 再点同一个 tile 第 2 次 → 切换状态：没加入技能组就加入，已加入就卸下

#### 技能组调整的**唯一入口**

**只能在编队界面调技能组**。角色页面**不允许**调整技能组（只能看角色数值、羁绊、天赋进度、预留的"多形态技能形态选择"——目前游戏里还没有多形态技能）。

#### 技能组内的同类内部顺序

**允许玩家手动拖拽调整**（比如拖拽"夏阳·燎原·连携"到"主角·拼命"前面），这个顺序会在自动重排序时被**稳定保留**。不同类之间不允许跨越拖拽（active 不能拖进 auto 块，拖进去时自动重排序会把它拉回来）。

## 五、回合与行动节点

### 5.1 一个完整回合（概念层）

```
回合开始
  ↓
我方回合 · 玩家操控阶段（主角 + 队友）
  ↓
我方回合 · 自动技能阶段
  ↓
我方回合 · 我方召唤物阶段
  ↓
我方回合 · 中立单位阶段
  ↓
敌方回合（敌方单位逐个执行）
  ↓
回合结束 → 回到回合开始，或战斗结算
```

### 5.2 行动节点（Action Node）

**专为程序员设计的术语**（不面向玩家）。用于规范 buff/debuff、结界、境界的持续时间结算时机。

**每个实体的行动节点 = 该实体在一个回合内第一次主动行动前的那一瞬间。**

规则：
- 每个实体每回合**只能有 1 次**行动节点触发
- **连携技能不触发行动节点**（因为连携可以在任何时刻插入，不是在该实体的操作阶段使用）
- 行动节点是**原子操作**，不可被打断、不可被连携插入、内部的元素附着判定必须等节点全部完成后才重新接受反应判定
- 硬控制单位**仍然会触发节点**（节点先扣冻结/束缚持续时间；扣到 0 则本次行动前状态消失可以行动，否则跳过本回合）

#### 持续效果挂在谁的节点上（表格，记忆用）

| 效果种类 | 结算时机 | 节点挂载对象 |
|---|---|---|
| 单位自身的 buff / debuff | 该单位的行动节点开始时 -1 | **承受者**（谁身上带着，就挂谁的节点） |
| 结界 Zone（燃烧/感电/超导）—— **由元素反应产生** | 每个结界**自己的独立行动节点**开始时 -1（产生时与触发者节点对齐，后续**完全不依赖触发者**） | 触发者死亡 → 结界仍然存活、仍能自己扣时间、仍能正常执行效果 |
| 其他结界（如敌人技能 / 我方技能产生的结界）—— **由技能产生** | **触发者**的行动节点开始时 -1 | **完全依赖触发者**。触发者死亡 → 结界立即消失（因为它的节点再也不会被触发） |
| 境界 Realm | 触发者的行动节点开始时 -1 | **触发者** |
| 防御护盾 | **该单位的行动节点触发时**（与回合开始几乎一致，"回合开始"是玩家视角、"行动节点"是程序员视角） | — |
| 技能冷却 | 每个敌方回合末尾 | — |

#### 护盾（防御护盾）

规格里"防御力"的定义：

> 该单位**轮到自己行动时**（行动节点触发瞬间），获得等同于 100% 局内防御力的护盾。

- 时机 = 该单位的行动节点触发瞬间（规格曾用"回合开始"这个说法，那是给玩家看的口语化表达；程序员应理解为**行动节点**）
- **即使召唤物 / 中立单位中途进入战场，只要它这一回合轮到行动、触发自己的行动节点，就会正常拿到护盾**
- 只有 100% 防御力加成的那一个护盾，没有其他来源的额外防御护盾
- 永久物品里的天赋类（如【坚守】【格挡】）也走这条通用规则

### 5.3 速度（speed）

- **只有主角和敌方有**
- **不影响行动顺序**（行动顺序全由状态机决定：玩家→自动→召唤物→中立→敌方）
- **只影响逃跑概率**
- 范围 0 ~ 999

### 5.4 行动力（actionPoint）

**只在探索中使用**。战斗中不消耗、不显示、没有意义。

- 探索里的每次移动 / 原地踏步 / 空地搜索 都会消耗
- 永久物品 `tent`（帐篷）让行动力上限 +1
- 睡觉恢复满

## 六、阵营与行为优先级

### 6.1 索敌规则（三条铁律）

**技能描述已经把索敌逻辑编码进去，分三种：**

| 技能描述文本 | 地块附着 | 实体伤害 |
|---|---|---|
| "对 xx 范围造成 xx 元素伤害" | 对**范围内所有非外部地块**都施加（不管地块上有没有实体） | 对**范围内所有可攻击的敌对阵营实体**造成 |
| "对 xx 范围内的 xx 阵营的 xx 单位造成 xx 元素伤害" | 只对**符合条件的单位所在地块**施加 | 只对**符合条件的单位**造成 |
| "对 xx 范围内造成不分敌我的 xx 元素伤害" | 对**范围内所有非外部地块**都施加 | 对**范围内所有可攻击的实体**（自身/我方/中立/敌方）造成 |

### 6.2 没有合法目标时的三类技能行为

| 技能类型 | 没目标时能否释放 | 消耗技能次数 | 触发节点 | 转冷却 |
|---|---|---|---|---|
| **主动技能** | ❌ **不允许释放**，弹文字提醒"当前没有可命中的目标" | ❌ | ❌ | ❌ |
| **自动技能** | ❌ 直接跳过，跳到下一个自动技能槽 | ❌ | ❌ | ❌ |
| **连携技能** | ⚠️ **窗口开启前必须有合法目标**；窗口打开后玩家按 E 期间可能目标消失 —— 仍然可以触发，但效果空转、**进入冷却** | ❌（连携本来就不消耗手动次数） | ❌（连携本来就不触发节点） | ✅ 是 |

"合法目标"广义定义：自身 / 队友 / 敌人 / 地块，其中至少有一个能被该技能命中就算合法。纯自 buff 技能：自身是合法目标，允许释放。

## 七、buff / debuff / 结界 / 境界

### 7.1 对照总表

| 维度 | buff / debuff | 结界 Zone | 境界 Realm |
|---|---|---|---|
| 本质 | 单位的状态修饰 | 与**地块**绑定的**范围效果** | **全场唯一**的**全局效果** |
| 绑定对象 | 某个实体 | 某个地块 | 战斗全局（不绑定地块） |
| 持续时间节点 | 承受者的行动节点 | 触发者的节点；但燃烧/感电/超导**独立计时器** | 触发者的行动节点 |
| 同名叠加规则 | 独立判定（大多不可叠加，少数可叠加单独说明） | 大多**立即替代**；燃烧/感电/超导**允许独立存在**（多格同时生效） | **全局唯一**（一个境界在时禁止开第二个） |
| 视觉表现 | 单位状态栏的彩色 chip（buff 金色、debuff 红色），显示剩余回合数 | 地块上的范围特效 | 全屏淡色叠加 + 右上角独立计时器 |
| 效果范围 | 只影响**自己**（一个单位） | 影响**范围内所有符合条件的单位**；离开范围立即移除结界给予的效果 | 影响全场所有指定单位 |
| 产生来源 | 技能、元素反应、回合开始护盾、天赋 | 元素反应（燃烧/感电/超导）、敌方技能、我方技能 | 特殊 Boss / 我方境界技能 |
| 能否被驱散 | ✅ 净化类技能可移除 | ❌ 不可直接驱散，只能等自然衰减或被新结界覆盖 | ❌ 不可驱散 |

### 7.2 典型交互

- 结界 → buff：燃烧结界给范围内单位加【燃烧】debuff（debuff 挂在承受者自己的行动节点上，跟着承受者走）
- 境界 → buff：全局【攻击力+50%】境界 → 全场我方单位各自获得攻击力 buff（衰减节点是触发者的，不是承受者的）
- 境界 vs 结界：境界优先级高于结界的"范围"概念（有境界存在时，境界仍然生效，结界的范围 buff 也仍然生效，但境界的**全局**效果不会因单位离开某个结界范围而消失）

## 八、硬控制效果

### 8.1 硬控制的**完整禁止清单**

被硬控制的单位，以下动作**全部被禁止**（按键本身可以按下，但按下后无实际效果、不会触发）：

- ❌ 主动技能（UI 变灰、快捷键拦截、逻辑层拒绝）
- ❌ 自动技能（自动技能阶段直接跳过这个槽）
- ❌ 连携技能（作为**所属角色**的连携，连携窗口不会为硬控角色的连携打开）
- ❌ 移动（包括"面向障碍格只转向"这种也算）
- ❌ 跳过（F 键按了也无响应）
- ❌ 逃跑（逃跑按钮无效）

### 8.2 硬控制的**按键不拦截**特性（规格强约束）

虽然硬控制禁止一切主动动作，但**按键事件不会被代码层面拦截**（这是为了避免 UI 弹错干扰玩家习惯性操作）—— **更重要的原因**：移动/跳过是玩家**结束自己回合的必要按键**，游戏里**不打算设置"结束回合"按钮**，必须玩家靠移动或跳过结束回合，因此**无论如何不能阻塞这两个按键**：

- 玩家被束缚时按 WASD → JS 事件正常发出，逻辑层里硬控制拦截让 `tryMovePlayer()` 早返回，**坐标不变、朝向不变、移动次数不消耗、行动计数不增加**
- 玩家被束缚时按 F → JS 事件正常发出，逻辑层里硬控制拦截让 `trySkip()` 早返回，**不结束手动阶段**
- 玩家被束缚时按 E → JS 事件正常发出，但连携窗口按前置条件里的"所属角色未硬控"规则自动关闭

**硬控制下能按下移动/跳过键，但按下后无实际效果**（这和"禁止按键"完全是两回事）。如果没有这条规则，硬控状态下玩家就无法结束自己的回合，会陷入死锁。

### 8.3 哪些状态属于硬控制（不完全列表，可扩展）

| 状态 | 来源 | 持续 | 特殊规则 |
|---|---|---|---|
| **冻结** | 元素反应 水+冰 | 2 回合 | 受火/雷伤害 → 本次伤害 +50% + **提前结束冻结** + 获得【免疫冻结·3回合】 |
| **束缚** | 敌人技能（如黏液喷射） | 3 回合 | — |
| **睡眠** | 特殊技能 | 2-3 回合 | 受任何伤害提前结束；不受免疫冻结保护 |
| **眩晕** | 暴击副产物等 | 1 回合 | — |

### 8.4 硬控制的**关键时序**（规格反复强调）

```
硬控单位轮到行动时：
  1. 先触发行动节点（节点先扣冻结/束缚的剩余回合数）
  2. 若扣到 0 → 状态消失 → 本次可正常行动
  3. 若没扣到 0 → 本回合跳过全部动作
  4. 节点标记"已触发"（所以本回合不会再触发）
```

**绝对不能反过来写成"先检查硬控、再触发节点"**——否则冻结单位永远扣不到持续时间，会被永远冻住。

### 8.5 队友被硬控 vs 主角被硬控

| 情况 | 主角的技能/行动 | 队友的技能/行动 |
|---|---|---|
| **主角被束缚** | ✅ 被硬控禁止一切 | 队友**不受主角束缚的任何影响**：可以自己放主动、自动、连携技能 |
| **队友被束缚** | ✅ 主角正常移动/放技能/跳过 | 队友被禁止一切主动动作；但**朝向仍然绑定主角**（主角转队友跟着转，这是"被动跟随"不是"主动控制"，不受束缚影响） |

## 九、元素反应（核心重做点）

### 9.1 总规则

1. 只在**战斗中**判定，探索中不判定
2. **元素反应优先级 = 游戏内最高**。一旦判定出反应，**立即暂停**当前一切：正在结算的伤害、正在施加的附着、敌人/我方行动、连携窗口、自动技能队列、扩散剩余圈等。全部处理完反应（含连锁），再恢复原上下文从断点继续
3. **同种元素**二次附着不反应也不叠加 → 地块上仍保持原附着；施加者白白浪费了这一次附着的语义（但**被视为"短暂存在过一瞬间"**）
4. **无法反应的异种组合** → 后者取代前者（地块附着换成后者）
5. 每次反应后**立即清空该地块的元素附着**（允许后续再施加，那是新的事）
6. 先后顺序**大多数反应不影响效果**（蒸发、融化**明确会影响**，见下）
7. 硬性兜底：**任何情况下不允许三个元素同时存在**（第三者会被强行丢弃不处理）

### 9.2 十种元素反应定义

#### 蒸发（水+火）—— 顺序敏感

| 顺序 | 效果 |
|---|---|
| 火 → 水（水触发） | 触发者获得 1 层【蒸发·水】：下一次**水属性伤害**的最终伤害 +50% |
| 水 → 火（火触发） | 触发者获得 1 层【蒸发·火】：下一次**火属性伤害**的最终伤害 +25% |

- 两种 buff **独立**、各自**至多叠加 2 层**（+50%/+100%）
- 持续无限直到被使用
- 消耗：触发效果时**一次性消耗所有层数**（不是消耗 1 层）
- 多段伤害的技能里**只有第一段伤害**会触发蒸发，后续段数不触发

#### 燃烧（火+草）

- 在该地块展开持续 3 回合的**燃烧结界**
- 燃烧结界**允许多个同名独立存在**（多格同时有各自的燃烧结界）
- **结界自身的行动节点**时（刚生成时不算）→ 对周围 4 格的已经受草元素附着的地块施加火元素附着（触发者视为这个燃烧结界本身）
- 燃烧结界所在地块若受到水元素或冰元素附着 → 本格燃烧结界**立即消失**
- 任何单位**位于该结界内**时获得持续 3 回合的【燃烧】debuff（挂在承受者的行动节点上；若原本有该 debuff 但剩余回合 < 3 则增加到 3 回合），**离开该结界后 debuff 仍然存在**（因为 debuff 已经转移到了承受者身上，不再挂在结界上）

#### 超载（火+雷）

- 对该地块**周围 5 格**（含自身格）内的**与触发者敌对的单位**造成相当于触发者 **50% 基础攻击力**的**火属性伤害**

#### 融化（火+冰）—— 顺序敏感

| 顺序 | 效果 |
|---|---|
| 火 → 冰（冰触发） | 触发者获得 1 层【融化·冰】：下一次**冰属性伤害**的最终伤害 +25% |
| 冰 → 火（火触发） | 触发者获得 1 层【融化·火】：下一次**火属性伤害**的最终伤害 +50% |

- 规则同蒸发：各自至多 2 层、无限持续、触发时消耗所有层数、多段只第一段触发

#### 扩散（火风 / 水风 / 雷风 / 冰风）

- 对**周围 9 格**造成相当于触发者 **30% 基础攻击力**的**该种元素属性伤害**
- 扩散反应很容易触发连锁反应。**扩散处理有特殊时序规则**：
  1. 先处理引发扩散的**原地块本身**（原地块反应完 → 附着清空 → 原地块现在应该是干净的，扩散效果不会对它造成新反应）
  2. 然后从**正上方的地块**开始，按顺时针方向依次触发扩散效果
  3. 若扩散效果在某个地块上引发了新的元素反应，**该新反应先记录**，但**先把这一圈扩散做完**，再按照记录顺序去处理连锁反应

#### 结晶（火岩 / 水岩 / 雷岩 / 冰岩）

- 触发者立即获得相当于自身**基础生命值上限 8%**的**护盾**（至少为 10 点）
- **队友触发结晶时**，改为让**主角**享受效果（队友没有生命值系统）

#### 绽放（水草）

- 在**周围 9 格内的非实体地块**召唤 1 只属于触发者阵营的**草史莱姆**
- **优先选择该地块本身**（自身格若非实体则召唤在自身格）
- 若周围 9 格全部都是实体地块 → 不召唤
- 草史莱姆没有特定数值，可作为占位

#### 感电（水电）

- 在该地块展开持续 3 回合的**感电结界**
- 然后触发者对所有**处于感电结界内的与触发者敌对的单位**造成相当于触发者 **25% 基础攻击力**的**雷属性伤害**
- 感电结界**允许多个同名独立存在**
- 感电结界所在地块若**处于水元素地块**（在本次反应之后新附着的） → 该感电结界持续时间**不随时间减少**（锁死 3 回合）

#### 冻结（水冰）

- 使**该地块上的实体**获得持续 2 回合的【冻结】debuff
- 冻结者受到**火属性伤害或雷属性伤害**时：本次伤害**最终 +50%** + **提前结束冻结**
- 无论以何种方式结束冻结，该单位立即获得持续 3 回合的【免疫冻结】

#### 激化（草雷）

- 使**触发者所在阵营的所有单位**各自获得 2 层【激化】buff
- 【激化】效果：下 1 次造成**草属性伤害或雷属性伤害**提升 10%（每层）
- 持续时间：**无限**直到触发效果
- 至多叠加 **10 层**
- 触发效果时**消耗 1 层**
- 一次技能若造成多段伤害 → **每段伤害分别消耗 1 层**

#### 超导（雷冰）

- 在该地块展开持续 3 回合的**超导结界**
- 超导结界内的单位：**雷、冰、物理抗性 -40%**（至少 -10）
- 超导结界**允许多个同名独立存在**
- 单位**离开该结界时，立即移除该结界给予的抗性减益效果**

### 9.3 反应优先级与处理栈

元素反应是**同步不可打断**的处理栈：

```
触发元素附着 → push 进 reactionStack
while reactionStack 非空:
  弹出最顶部 reaction
  执行该反应的完整效果：
    （伤害 / 护盾 / 召唤 / 生成结界 / 给 buff / 清空地块附着）
  该反应效果中若产生新附着 → push 进 reactionStack
  扩散特殊处理：所有扩散子效果 push 进 diffusionQueue
  → 等扩散 Queue 全部执行完，再处理 diffusionQueue 里产生的新反应
reactionStack 为空 → 恢复原上下文继续
```

### 9.4 关于"触发者"（规格强调过）

反应的"触发者" ≠ 站在该地块上的单位，而是 **施加第二种元素附着的单位**（谁打的第二个附着，谁就是触发者）。蒸发、融化、超载、扩散、结晶、绽放、感电、激化、超导都用这个规则。

燃烧的"自身行动节点施加火附着"——这里的触发者**视为这个燃烧结界本身**（不是任何实体）。

## 十、行动与行为计数

### 10.1 概念分层

| 计数维度 | 范围 | 上限 | 与其他计数的关系 |
|---|---|---|---|
| **技能使用次数** | 每角色独立 | 每角色本回合 1 次 | 与移动/跳过**完全独立**，互不影响。移动了不会少技能次数，放了技能不会少移动次数 |
| **移动次数** | 主角 | 1 次（风元素地块双动 +1 次） | 双动是**额外多 1 次特殊移动机会**，不能算作额外的技能次数 |
| **行动计数** | 仅主角（队友行动不算） | 无硬上限，但**逃跑按钮的禁用门槛**是"行动计数 ≥ 1" | 主角做的以下所有事都算：放主动/自动技能、移动、跳过、原地踏步、触发连携、自动技能阶段自动释放自己的自动技能 |

### 10.2 行动计数的精确清单

以下全部是**主角的行动**（`G.hero.actionCountThisTurn += 1`）：

- ✅ 放了任何主动技能（不管有效无效、不管有没有目标）
- ✅ 移动（包括成功移动、面向障碍格只转向、原地踏步）
- ✅ 按 F 跳过（哪怕硬控制下按键发出了但效果空转，**只要按键事件发出就算行动**）
- ✅ 触发了任何连携技能（哪怕连携因为没目标效果空转）
- ✅ 自动技能阶段自动释放了主角自己的自动技能

**以下不算主角的行动**：

- ❌ 队友自己放技能 / 队友的任何主动动作
- ❌ 连携释放的是**队友的连携技**（连携所属角色是队友，主角按下 E 键是"触发"，不是"执行"）
- ❌ 切换当前选中角色（主角 ↔ 夏阳 ↔ 陆悠悠）—— 这是纯 UI 操作

### 10.3 逃跑按钮禁用

```
canFlee = (
  主角正处于玩家操控阶段
  && G.hero.actionCountThisTurn === 0
  && 主角未受硬控制
)
```

逃跑按钮**只能在主角回合开始瞬间**可见可按。主角一旦做了任何行动（哪怕只是按了一下 F），逃跑按钮立即置灰。

### 10.4 逃跑失败的后续

- 主角：**视为跳过回合**（手动阶段直接结束）+ **失去技能使用次数**（本回合主角不能再放主动技能了）
- 队友：**不受任何影响**（队友仍然保留技能次数，可以继续放主动/自动技能）

### 10.5 残存时间（规格唯一描述）

> 玩家想结束自身回合的手段有且只有两种：1. 以任何方式移动（是否实际改变位置或朝向无所谓）；2. 不移动，直接按 F 跳过回合。
> 举例：若玩家未使用一个角色的主动技能，则自身回合结束时，该角色还有次数可以使用自动技能，若该角色携带了多个自动技能，则只能使用最靠前的且能够使用的自动技能。
> 特别地，玩家移动或跳过后，若还有技能使用次数，则会留出 1 秒的【残存时间】（不显示在 UI 上但的确存在），供玩家在此时仍可使用主动技能，一旦使用主动技能，立即重置残存时间（方便玩家继续使用其他角色的主动技能）。若玩家在残存时间内未使用技能，才真正的视为结束了本回合的手动操作阶段。若编队中所有角色都已经没有技能使用次数，则移动或跳过后不给予残存时间。

### 10.6 主动技能释放的前置硬门槛（规格要求）

- **没有合法目标 → 不允许释放**（UI 提示"当前没有可命中的目标"，不消耗次数、不转冷却、不触发节点）
- 纯自 buff 技能：自身是合法目标，可以释放
- 自 buff + 对敌效果并存的技能：**只要技能效果里至少有一部分有合法目标**就允许释放（对敌部分可能打空，但自 buff 仍然触发）

## 十一、战斗中的元素附着清除

战斗开始时，`combatState` 会对地图当前状态做一份快照，包含地块上已有的元素附着。战斗结束后（无论胜利、失败、逃跑），地图状态被回滚/覆盖到快照（**或按规则保留附着**，当前实现待后续明确），下一日生成新地图时统一清除全部附着。

## 十二、胜负与异常退出条件

**任何一条满足即立即退出战斗，优先级高于一切（高于元素反应、高于连携、高于行动节点）：**

| 条件 | 结算类型 | 后续 |
|---|---|---|
| 敌方全灭 | 胜利 | 回到进入点，还原朝向，给奖励 |
| 主角死亡 / 生命值归零 | 失败 | 回到进入点，还原朝向，按敌人种类扣健康；健康归零 → 全局失败（直接退出游戏流程） |
| 逃跑成功 | 逃跑 | 回到进入点，还原朝向，不给奖励 |
| 健康归零（战斗中 / 探索中任何时刻） | 全局失败 | 直接退出游戏流程 |

## 十三、冷却

- 每个技能有 `cd` 字段（未声明默认 1 回合）
- **冷却扣减时机 = 敌方回合末尾**（所有敌方执行完后统一 tick 一次）
- 冷却扣减是全局 tick，**不是"释放后立即 -1"**。释放时赋值 `slot.cd = skill.cd` 只是把冷却设为"技能声明的数值"，真正 -1 要等敌方回合末尾

## 十四、装备载具时跳过对载具次数的消耗（战斗中）

**探索时**：每次移动 / 原地踏步都消耗 1 次载具 uses（徒步跋涉、疾行因为 infinite:true 所以永远不会真耗尽）。

**战斗时**：按 F 跳过也算 1 次载具 uses（规格明确）。战斗中的正常移动也消耗 1 次载具 uses。
