# 战斗系统规格 v2

> 本文件为 **游戏战斗系统的唯一权威规格**。若与旧文档（已归档）内容冲突，**以本文档为准**。
> 版本：2026-09-27。主目标：对战斗系统整体进行超大幅度重做。允许修改一切战斗有关代码，理论上不改变探索（非战斗）以及剧情/事件代码，但因接口改变或其他必要原因可适当修改。

## 0. 核心概念对照（术语表）

| 术语 | 定义 |
|---|---|
| **地块** | 地图由格子组成，每一格称为地块。是严谨的面向玩家的说法。在前端所有玩家可见处统一用"地块"。代码中"格子"与"地块"同义。 |
| **实体 / 单位** | 每个地块在战斗或探索中，至多一个实体。实体 = 可移动/可被攻击/有生命值的东西（主角、队友、敌人、召唤物）。单位为不太严谨的同义词。 |
| **元素** | 特指 **火 水 草 雷 冰 风 岩** 7 种。"物理" 不属于元素。 |
| **回合** | 我方一整个行动阶段 + 敌方一整个行动阶段 = 一个回合。 |
| **阵营** | 我方 / 中立 / 敌方。中立有细分，用到再说明。 |
| **buff / debuff** | 游戏效果，显示在状态栏。同名效果能否叠加单独说明。 |
| **结界** | 与地块相关的范围效果，给范围内单位加 buff/debuff，通常有特效。同名结界多数会**立即替代**旧结界；少数允许独立存在（会特殊说明：**燃烧、感电、超导** 允许同名独立）。不同名结界互不干扰。 |
| **境界** | 全场唯一的效果。一个境界存在时，禁止任何方式打开第二个境界。有计时器显示。 |
| **地块类别** | **空地块 / 元素地块 / 实体地块 / 元素实体地块 / 地形 / 空地 / 作战 / 紧急作战 / 事件 / 奖励 / 外部地块**（见 §1）。 |
| **元素附着** | 只能附着在**地块**上（核心重做点！原代码中风/岩不能附着 → 现在 7 种都能）。不属于实体。一层地块至多一层附着。第二层附着触发元素反应判定。 |
| **x 属性伤害** | 造成 x 元素伤害**但不施加附着**。无法引起元素反应。 |
| **x 元素伤害** | 先施加一次 x 元素附着，再造成一次 x 属性伤害。若因附着触发元素反应，**先结算反应效果，再结算属性伤害**。 |
| **x 元素抗性** | 受到 x 属性伤害减少/增加的百分比。最终约束 -100 到 +90。物理抗性也属于元素抗性一种。 |
| **索敌目标规则** | 见 §2。 |
| **元素反应** | 见 §3。优先级最高（除战斗结束）。 |
| **行动节点** | 程序员专用。每个单位**本回合第一次主动行动**前一瞬间，用于结算 buff/结界/境界持续时间。连携技能**不触发**行动节点。 |
| **局内属性 / 基础属性** | 局内 = 基础 + 战斗中临时加成。战斗结束自动还原为基础。攻击力 / 最大生命值 / 防御力 均如此。 |
| **行动约束** | 见 §6。主角+队友是一体的，队友没有独立移动/跳过操作。 |
| **技能组** | 编队级别，全体共用。初始 4 槽，编队人数（含主角）每 +1 解锁 1 新槽，新槽**只能放自动/连携**。总上限 10。自动/主动/连携 按类型排序，同类内部按角色在编队中的顺序再按该角色的技能顺序。 |

## 1. 地块类别

每格有唯一类型：

- **空地块**：上面没有实体、没有元素附着。战斗中严谨称谓。
- **元素地块**：有元素附着（不管有没有实体）。
- **实体地块**：有实体在上面（不管有没有附着）。
- **元素实体地块**：同时有实体 + 元素附着。
- **地形**：大类（山、河流、冰面、草地等），具体性质看具体地形。
- **空地 / 作战 / 紧急作战 / 事件 / 奖励**：探索中显示的图标属性。**战斗开始时隐藏并失去所有效果，战斗结束重新出现**。被玩家进入过后变为空地。
- **外部地块**：地图边界，不可进入、不接受任何效果或附着。代码中原名 void → 统一叫外部地块。

### 数据模型

```js
// 地块
{
  x, y, n,            // 坐标
  terrain,            // 地形大类（void|mountain|river|grass|ice|swamp|rock...）
  attach: null|'fire'|'water'|'grass'|'thunder'|'ice'|'wind'|'rock',  // ★ 元素附着单字段
  category: null|'battle'|'hardBattle'|'event'|'reward',  // 探索类别（战斗时隐藏）
  entityId: null,     // 占用该格的实体 id
}

// 外部地块：terrain === 'void'
// 空地块：  attach === null && entityId === null
// 元素地块：attach !== null && entityId === null
// 实体地块：attach === null && entityId !== null
// 元素实体：attach !== null && entityId !== null
```

## 2. 索敌目标规则（核心修改）

**原代码过时。** 三条规则：

1. **"对 xx 范围造成 xx 元素伤害"**（未指定阵营）→ 对范围内**所有可攻击实体**（默认不含自身/我方/中立）造成伤害；对范围内**所有非外部地块**施加元素附着。
2. **明确写了阵营筛选**（如"对 xx 范围内的敌方单位"）→ 严格按描述筛选。不额外给不符合条件的地块加附着、也不给不符合条件的实体造成伤害。
3. **写了"不分敌我"** → 对范围内**所有实体**（含自身、我方、中立、敌方）造成伤害；对范围内所有非外部地块施加附着。

## 3. 元素附着规则

1. 一个地块**至多一层**元素附着。第二层附着立即触发反应判定。
2. 地块上的实体如何移动**不清除**地块的附着。
3. **7 种元素全部可附着**（原代码中风/岩不能 → 重做后全部可）。
4. 附着**只在战斗中施加**。探索中无法施加。
5. 附着在战斗结束时**不清除**。会保留到下一日新地图生成时才清除。
6. 元素反应判定：见下。

---

## 4. 元素反应（最高优先级，除战斗结束）

### 4.1 基本规则

1. 只在战斗中判定。
2. **元素反应暂停一切**：伤害计算、元素附着施加、敌我行动、自动技能、连携、扩散剩余圈等 → 全部挂起。
3. 同种元素 + 同种元素 → **不反应、不叠加**，保持原样。
4. 不可反应的组合 → 后者**直接取代**前者附着。
5. 可反应组合（见 §4.2）：**先后顺序对效果有影响**（蒸发、融化、扩散、燃烧、感电、冻结、结晶、绽放、激化、超导）。
6. 反应结束后**立即清空该地块的全部附着**。
7. 硬性兜底：**一个地块绝不允许 3 层附着同时存在**。
8. 反应发生瞬间，视为**第二种元素短暂出现过**（影响后续一些判断）。
9. 反应期间可能触发连锁反应（如扩散到周围地块又触发新反应）。**当前反应 + 全部连锁 都处理完**才能恢复主流程。

### 4.2 具体反应组合

| 反应 | 组合 | 效果 | 先后影响？ |
|---|---|---|---|
| **蒸发** | 火+水（先火后水）<br>水+火（先水后火） | 先水后火 → 触发者获得 **蒸发·火**（下次火伤害 +25%，最多 2 层 +50%，消耗所有层）<br>先火后水 → 触发者获得 **蒸发·水**（下次水伤害 +50%，最多 2 层 +100%，消耗所有层）<br>多段伤害只第一段触发 | ✅ 是 |
| **燃烧** | 火+草 | 该地块展开 **持续 3 回合的燃烧结界**（燃烧结界允许多个同名独立存在）<br>结界在自身行动节点时（刚生成时不算）对周围 4 格已受草附着的地块**施加火附着**（触发者视为这个燃烧结界本身）<br>受到水或冰附着 → 该格燃烧结界立即消失<br>位于结界内的单位获 **【燃烧】debuff**（3 回合，离开后仍存在） | — |
| **超载** | 火+雷 | 对**该地块周围 5 格**（含自身）与**触发者敌对**的单位造成 **50% 基础攻击力的火属性伤害** | — |
| **融化** | 火+冰 | 先冰后火 → 触发者 **融化·冰**（下次冰伤害 +25%）<br>先火后冰 → 触发者 **融化·火**（下次火伤害 +50%）<br>各自最多 2 层、独立、消耗全部层触发 | ✅ 是 |
| **扩散** | 风+火/风+水/风+雷/风+冰 | 对**周围 9 格**造成 **30% 基础攻击力的该种元素伤害**<br>（举例：风+火 → 周围 9 格火元素伤害）<br>可能触发连锁反应 → **先处理完这一圈（顺时针从上开始），再按记录处理连锁** | — |
| **结晶** | 火+岩/水+岩/雷+岩/冰+岩 | 触发者立即获得 **8% 基础生命上限的护盾（至少 10）**<br>队友（无生命值）触发 → 主角享受效果 | — |
| **绽放** | 水+草 | 周围 **9 格内的非实体地块** 召唤 1 只 **草史莱姆**（属于触发者阵营）<br>优先选择该地块本身。周围都不是非实体 → 不召唤 | — |
| **感电** | 水+雷 | 该地块展开 **持续 3 回合的感电结界**（允许多个同名独立存在）<br>然后触发者对**所有处于感电结界内的敌对单位**造成 **25% 基础攻击力的雷属性伤害**<br>若感电地块处于水附着 → 持续时间**不衰减** | — |
| **冻结** | 水+冰 | 该地块上的单位获 **【冻结】debuff（2 回合）**：无法行动<br>受到火或雷伤害 → 本次伤害最终 +50%，且提前结束冻结<br>任何方式结束冻结 → 获得 **【免疫冻结】debuff（3 回合）** | — |
| **激化** | 草+雷 | 触发者**所在阵营**所有单位各自获 **2 层【激化】buff**：下次草/雷伤害 +10%<br>最多 10 层，每次触发消耗 1 层<br>多段伤害每段消耗 1 层 | — |
| **超导** | 雷+冰 | 该地块展开 **持续 3 回合的超导结界**（允许多个同名独立存在）<br>结界内单位 **雷、冰、物理抗性 -40%（至少 -10）**<br>离开结界立即移除 | — |

### 反应优先级表（运行时）

```
1. 战斗结束判定        ← 最高
2. 元素反应 + 连锁反应  ← 暂停一切
3. 连携技能
4. 自动技能队列
5. 正常行动（玩家/召唤物/AI）
```

## 5. buff / debuff / 结界 / 境界

### 数据模型

```js
// 单位身上的 buff/debuff（挂在实体 id 上）
{
  entityId: 'pro',
  type: 'evaporate_water',  // buff id
  stacks: 2,                // 层数（对蒸发/融化/激化这类有用）
  duration: Infinity,       // 剩余回合数；挂在单位自身的行动节点上衰减
  triggerNodeEntityId: 'pro',  // （可选）对结界的 debuff：debuff 持续时间挂在承受者的节点上
}

// 地块上的结界（挂在地块坐标上）
{
  kind: 'burn' | 'electric' | 'superconduct',
  x, y,
  duration: 3,               // 剩余回合；挂在触发者的行动节点上衰减
  triggerNodeEntityId: <触发者 entityId>,
  independent: false         // 燃烧/感电：可能 independent→true（触发者死亡结界继续）
}

// 境界（全局唯一）
{
  kind: 'xxx',
  ownerEntityId,
  duration: 5,
}
```

### 持续时间衰减：行动节点

- **单位 buff/debuff**：挂在**承受者**的行动节点上（承受者第一次主动行动前 -1）。
- **结界持续时间**：挂在**触发者**的行动节点上。触发者死亡后，燃烧/感电/超导结界会转独立计时器继续，其他结界消失。
- **境界持续时间**：挂在 owner 的行动节点上。
- **连携技能不触发任何行动节点**。

## 6. 行动约束（主角 + 队友 = 一体）

### 核心规则

- 主角与队友**同回合、共享一次机会**。
- 每个角色**独立**：本回合 1 次主动/自动技能使用次数（连携不计）。
- 使用技能**不结束回合**。
- 结束回合的手段**只有两种**：
  1. 以任何方式**移动**（实际是否改变位置或朝向不重要）
  2. 按 **F 键**跳过回合
- 移动/跳过后**给予 1 秒残存时间**（不显示 UI），供玩家在残存时间内继续用**主动技能**。使用主动技能会**重置残存时间**。
- 残存时间内没用主动技能 → 真正结束手动操作阶段。
- 若**所有角色都没技能次数** → 移动/跳过后**不给予残存时间**。
- **逃跑失败**：主角视为跳过且失去技能次数；队友不受影响。

### 主动 / 自动 / 连携

- **主动技能**：主角行动期间手动点击或快捷键使用。玩家可控顺序。
- **自动技能**：玩家无法手动触发。**玩家操控阶段结束、下一个非玩家单位行动前**自动释放。按技能组顺序逐个检查：
  1. 未冷却
  2. 有合法目标
  3. 所属角色未受硬控制
  4. 所属角色还有技能次数
  5. 若该角色未触发行动节点 → 先触发节点再释放（保险）
  玩家移动/跳过后若还有技能次数，**自动技能释放最靠前的、能用的一个**。
- **连携技能**：条件满足即可点 **E** 键释放。2 秒窗口。可打断当前行动（极短原子操作除外）。多个可用 → 按技能组顺序排队轮流给 2s 窗口。**连携不触发行动节点**。

### 行动节点的硬控制

- **冻结**：轮到该单位时，仍触发行动节点。节点先扣冻结；若减到 0 → 本次可行动；否则跳过。
- **硬控制**（冻结/禁锢等）：阻止主动、自动、连携技能使用；阻止移动、跳过、逃跑。

## 7. 战斗主循环（分层状态机）

```
┌──────────────────────────────────────────────────────────┐
│ 回合开始                                                  │
│   · 回合计数 +1                                           │
│   · 重置所有实体：usedThisTurn=false, nodeTriggered=false  │
│   · 构建本回合行动队列                                      │
│                                                           │
│ ▼                                                         │
│ ┌──────────────────────────────────────────────────────┐ │
│ 我方回合                                                  │ │
│                                                           │ │
│ 1. 玩家操控阶段                                            │ │
│   · 主角可移动 / 跳过 / 使用主动技能                         │ │
│   · 队友可使用主动技能（顺序由玩家决定）                      │ │
│   · 逃跑尝试 → 先触发节点，计算概率                          │ │
│                                                           │ │
│   连携随时可用（2 秒窗口）                                   │ │
│                                                           │ │
│ ▼（玩家操控阶段结束 + 残存时间结束）                       │ │
│ 2. 自动技能阶段                                            │ │
│   · 按技能组顺序逐个检查自动技能                             │ │
│   · 满足条件则释放                                          │ │
│                                                           │ │
│   可被连携打断                                              │ │
│                                                           │ │
│ ▼（自动技能队列清空）                                       │ │
│ 3. 我方召唤物阶段                                           │ │
│   · 内部顺序由代码决定（生成顺序 / 位置 / entityId）           │ │
│   · 每单位先触发行动节点，再执行 AI                          │ │
│                                                           │ │
│ 4. 中立单位阶段                                             │ │
│   · 同召唤物，我方回合末尾                                   │ │
│                                                           │ │
│ ▼（我方阶段结束）                                          │ │
│ 敌方回合                                                   │ │
│   · 内部顺序由代码决定                                       │ │
│   · 每单位先触发行动节点，再执行 AI                          │ │
│                                                           │ │
│ ▼（敌方阶段结束）                                          │ │
│ 回合结束                                                   │ │
│   · 清理临时队列 / 连携窗口 / 自动队列                       │ │
│   · 进入下一回合                                            │ │
│                                                           │ │
│ └──────────────────────────────────────────────────────┘ │
│                                                           │
│ （任何阶段都持续检查战斗结束条件）                           │
└──────────────────────────────────────────────────────────┘
```

### 战斗结束条件（超高优先级，高于元素反应）

- 敌方全灭 → 胜利
- 主角死亡 / HP 归零 → 失败（按敌人种类扣健康）
- 逃跑成功 → 结束（不扣健康）
- 健康归零 → 全局失败，直接退出游戏

### 打断与恢复机制（上下文栈 + 事件队列）

```
元素反应：
  保存当前上下文 → 暂停一切 → 处理反应效果 + 连锁反应 → 恢复原上下文断点

连携技能：
  2 秒窗口发出事件 → 玩家按 E → 挂起原行动 → 按技能组顺序执行连携 → 恢复原行动

自动技能 + 连携：
  执行自动技能中 → 满足连携条件 → 连携插入 → 连携处理完继续自动队列
```

### 连携技能的 2 秒窗口流程

```
for slot in skillGroup (filter: auto):
  if cd==0 && hasTarget && !hardCtrl && meetsPrecondition(slot):
    emitLinkWindow(slot, 2s)       // 显示"按 E" 提示
    start = performance.now()
    awaitKey('E') 或 timeout(2s)
    if E pressed:
      saveCurrentContext()
      castLinkSkill(slot)
      restoreContext()
      // 连携执行完（含反应）
    else:
      continue  // 下一个可用连携
// 全部超时 → 回到原行动
```

## 8. 优先级总表

| # | 事件 | 优先级 |
|---|---|---|
| 0 | 战斗结束判定 | 最高 |
| 1 | 行动节点（每个单位独立，原子操作不可打断） | — |
| 2 | 元素反应（含连锁反应） | 暂停一切 |
| 3 | 连携技能 | 可打断当前行动 |
| 4 | 自动技能队列 | 可被连携打断 |

## 9. 技能与技能组

### 技能大类（**删除旧的"攻击/辅助/天赋"分类**，过时了）

- **主动技能**（active）：战斗中玩家手动使用
- **自动技能**（auto）：战斗中自动释放
- **连携技能**（link）：战斗中按 E 释放
- **天赋技能**（talent）：只要角色编入编队就生效，**无需加入技能组**，不受驱散/硬控制影响，探索+战斗都生效

```js
function validateSkillGroup(group, teamSize):
  if (group.length > Math.min(10, 4 + teamSize)) return false  // 上限
  for (let i = 0; i < group.length; i++):
    if (i >= 4 && group[i].kind === 'active') return false  // 槽 5+ 不能放 active
```

## 13. 行动节点触发时机（代码伪代码）

```js
function triggerActionNode(entity, combatState):
  if (entity.nodeTriggered): return    // 每回合只触发一次
  entity.nodeTriggered = true
  // 1. buff/debuff 衰减（挂在 entity 自身节点上的）
  for each buff in entity.buffs:
    buff.duration -= 1
    if buff.duration <= 0: 移除 buff
  // 2. 结界/境界 衰减（挂在 entity 节点上的）
  for each border in combatState.borders:
    if border.triggerNodeEntityId === entity.id:
      border.duration -= 1
      if border.duration <= 0:
        remove border
  // 原子操作，不可打断
```

## 14. 完整伪代码：我方回合入口

```js
function runAllyTurn(combatState):
  // 玩家操控阶段
  let manualPhaseDone = false
  let lingeringStart = null
  let activeCharsLeft = getAliveAllyChars().filter(c => !c.hardCtrl)
  
  while (!manualPhaseDone || lingeringStart !== null):
    // 等待玩家输入：移动 / 跳 / 主动技能
    let input = waitForInput()
    if (input.type === 'idle' && lingeringStart && now - lingeringStart > 1000):
      manualPhaseDone = true; lingeringStart = null; break
    if (input.type === 'skill'):
      let [charKey, skill] = input  // 主动技能
      if (!char.nodeTriggered) triggerActionNode(char)
      castSkill(char, skill)        // 可能触发连携 + 元素反应
      char.usedThisTurn = true
      lingeringStart = now          // 重置残存时间
    if (input.type === 'move' || input.type === 'skip'):
      let pro = combatState.entities['pro']
      if (!pro.nodeTriggered) triggerActionNode(pro)
      if (input.type === 'skip') pro.usedThisTurn = true
      if (allCharsUsedThisTurn()):
        manualPhaseDone = true; lingeringStart = null; break
      lingeringStart = now
  
  // 自动技能阶段
  runAutoSkillPhase(combatState)
  
  // 我方召唤物阶段
  runSummonPhase(combatState, 'ally')
  
  // 中立单位阶段
  runSummonPhase(combatState, 'neutral')
```

## 15. 行动节点 vs 元素反应 vs 连携（边界）

```
正常行动流程：
  triggerActionNode(entity)       // 1. 节点（原子、无附着）
  → castSkill / move              // 2. 正常行动
      → applyAttachments()        // 可能触发元素反应（暂停一切）
      → castDamage()
  
连携触发：
  正常行动进行到一半
  → 发现连携窗口
  → 暂停正常行动（保存上下文）
  → castLinkSkill()
      → 节点不触发（连携规则）
      → 可能触发元素反应
  → 恢复正常行动上下文
  
行动节点 + 元素反应：
  行动节点衰减 buff → 节点不会施加附着 → 不会触发反应
  正常行动施加附着 → 触发反应 → 暂停一切 → 反应 → 恢复
```

## 18. 护盾机制

```js
// 护盾作为独立字段（不是 buff/debuff）
entity.shield = shieldValue

// 扣血逻辑：
function applyDamage(entity, dmg):
  if (entity.shield > 0):
    absorbed = Math.min(entity.shield, dmg)
    entity.shield -= absorbed
    dmg -= absorbed
  entity.hp -= dmg
  if (entity.hp <= 0): entity.dead = true
```
