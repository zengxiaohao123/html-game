## 一、进入战斗

触发：踩到 `battle` / `emergency` / `reward` 类作战地块，或事件/剧情强制开战。

进入流程：

```
1. 构建 combatState 快照
   const cs = {
     // === 快照 ===
     playerSnap,              // 主角当前状态快照（HP、buff、朝向等）
     mapCopy,                 // 地图当前状态深拷贝（地形 + 附着 + 实体列表）
     skillGroup,              // 当前编队的技能组快照
     startPos,                // { x, y } 主角开战时位置（结束时还原用）
     startFacing,             // 主角开战时朝向（结束时还原用）

     // === 敌人进攻点 ===
     enemySpawnPoints: [      // 可多个（未来扩展）；默认只有 1 个
       { x, y },              // 地块坐标；不是实体；被占据不影响生成
     ],

     // === 实体 ===
     entities: Entity[],      // 全场所有实体（主角、队友、敌人、召唤物、中立、敌方新生成的）
     // 说明：不再分开 entities/enemies/pets 多套管理，全部统一在这一个数组里
     //       阵营 faction 字段区分 'player' / 'enemy' / 'neutral' / 'summon_player' / 'summon_enemy'

     // === 状态机 ===
     turn: 0,                 // 回合计数
     phase: 'roundStart',     // 当前状态机相位
     nodeTriggered: {},       // 每个实体本回合是否已触发节点 { entityKey: bool }
     usedSkillThisTurn: {},   // 每个实体本回合是否已用主动/自动技能
     usedMoveThisTurn: {},    // 主角本回合是否已移动
     actionCount: 0,          // 主角本回合行动计数
     pendingLinks: [],        // 当前连携候选队列
     linkActive: false,       // 连携窗口打开中
     lingering: 0,            // 残存时间剩余（毫秒）
     activeEnemyIdx: 0,       // 敌方回合当前轮到的敌人索引

     // === 碰撞伤害 ===
     collidedThisTurn: {},    // { enemyKey: bool } 该敌人本回合是否已造成过碰撞伤害

     // === 结界/境界 ===
     zones: [],               // 结界列表
     realm: null,             // 境界（全局唯一）
   }

2. 敌方初始生成（从敌人进攻点生成）
   · 默认每回合生成 1 个新敌人（本回合的第一个敌人）
   · 特殊说明时可一次生成多个

3. UI 切换
   · switchMode('combat') —— 底部切到 #combatZone（四行排版：角色卡+技能组 → 属性 → 天赋 → 状态芯片 + 右侧技能描述）
   · iconbar 禁用：编队、睡觉、商店、合成
   · HUD 刷新战斗态
   · 键盘切换到战斗按键映射

4. 日志："进入战斗。按 F 结束手动阶段，E 使用连携（若有）。"

5. 进入 roundStart 相位
```

### 1.1 敌人进攻点选格规则

```
选格逻辑：
  从地图上所有满足以下条件的格子中随机选一个：
    a. terrain 不是 'void'（可通行）
    b. 当前没有被标记为 isEnemySpawnPoint
  · 特殊说明：进攻点**不是实体**，不占据实体槽位
  · 进攻点**可以被实体占据**（主角、我方召唤物、新生成的敌人都可以走上去）
  · 进攻点被实体占据**不影响敌人生成**（新敌人仍然会生成在该进攻点坐标）
```

## 二、回合状态机（分层）

```
┌─────────────────────────────────────────────────────────────┐
│ roundStart                                                  │
│                                                             │
│   turn += 1                                                 │
│                                                             │
│   重置所有实体本回合标记：                                    │
│     nodeTriggered = {}                                      │
│     usedSkillThisTurn = {}                                  │
│     usedMoveThisTurn = {}                                   │
│     actionCount = 0                                         │
│     collidedThisTurn = {}                                   │
│                                                             │
│   从敌人进攻点生成本回合敌人（默认 1 个，特殊说明时多个）       │
│                                                             │
│   phase = 'playerManual'                                    │
├─────────────────────────────────────────────────────────────┤
│ playerManual 玩家操控阶段                                    │
│                                                             │
│   玩家可做的操作（见 §三）：                                  │

│     · 按 WASD 移动 / 点相邻格前往 / 原地踏步                 │
│     · 按 F 跳过                                             │
│     · 按 E 连携（有窗口时）                                  │
│     · Esc / 逃跑按钮                                        │
│                                                             │
│   结束条件：                                                 │
│     · 残存时间归零                                          │
│     · 所有活着角色的 usedSkillThisTurn 都为 true              │
│     · 主角逃跑成功（特殊退出）                                │
│     · 主角死亡（特殊退出）                                    │
│                                                             │

│     若所有角色都没次数了 → 直接 phase = 'autoSkills'          │

│ autoSkills 自动技能阶段                                     │
│                                                             │
│   遍历技能组里 kind === 'auto' 的槽：                        │
│     · 检查前置条件（冷却 / 硬控 / 目标 / 次数）              │

│     · 冷却设为 sk.cd                                        │

│                                                             │
│   每释放一个自动技能间隙 → _checkLinkWindow()                │
│                                                             │
│   phase = 'summons'                                         │
├─────────────────────────────────────────────────────────────┤
│ summons 我方召唤物阶段                                       │
│                                                             │
│   按固定顺序逐个执行：                                        │
│     triggerNode(summon)                                     │
│     summonAI(summon)                                        │
│                                                             │
│   全部执行完 → phase = 'neutral'                             │
├─────────────────────────────────────────────────────────────┤
│ neutral 中立单位阶段                                         │
│                                                             │
│   按固定顺序逐个执行：                                        │
│     triggerNode(entity)                                     │
│     neutralAI(entity)                                       │
│                                                             │
│   全部执行完 → phase = 'enemy'                               │
├─────────────────────────────────────────────────────────────┤
│ enemy 敌方回合                                               │
│                                                             │
│   按固定顺序（x+y 升序 + entityKey 字典序）逐个执行：          │
│     triggerNode(enemy)           ← 先扣冻结/束缚持续！        │

│     else enemyAI(enemy)                                      │
│       → enemyAI 内部：执行敌人移动 → 移动中触发碰撞伤害判定    │
```

## 三、玩家操控阶段的每一个操作

### 3.1 操作技能组放主动技能

```
tryCastActiveSkill(slotIdx):
  const slot = cs.skillGroup[slotIdx]
  const owner = slot.charKey                    // 技能 owner 追溯到具体角色

  preconditions:
    slot.kind === 'active'
    !cs.hardControl[owner]                      // owner 没硬控
    !cs.usedSkillThisTurn[owner]                // owner 本回合没用过技能
    slot.cd === 0                               // 冷却好了
    hasValidTargetForSkill(slot)                // ⚠️ 规格硬门槛

  → 不满足 → UI 弹红色提示，立即 return

  // owner 第一次主动行动 → 触发 owner 的行动节点（注意：是 owner 的节点，不是主角的）
  if !cs.nodeTriggered[owner]:
    triggerNode(owner)

  resolveSkill(slot, owner, source='playerManual')

  cs.usedSkillThisTurn[owner] = true
  slot.cd = slot.cdDecl || 1

  // 主角行动计数 +1（主角是发起操作的人）
  cs.actionCount += 1

  // 主角行动节点也需要在主角第一次主动行动时触发（如果之前没触发）
  if !cs.nodeTriggered['pro']:
    triggerNode('pro')

  // 每次主动释放 → 残存时间重置 1 秒
  cs.lingeringTimer = 1000
```

**关键说明**：
- **玩家不需要切换角色**，直接操作技能组放技能即可
- **owner 追溯**：技能数据里有 `charKey` 字段，明确这个技能"归属"哪个角色。释放时 `nodeTriggered`、`usedSkillThisTurn`、冷却都记在 owner 头上
- **范围朝向**：所有技能的范围严格按**主角当前朝向**计算，**不自动校准**。如果当前朝向里没有合法目标 → 主动技能直接禁止释放

### 3.2 WASD 移动 / 点相邻格

```
tryMovePlayer(dir):
  pre: 主角没硬控

  cs.actionCount += 1
  cs.usedMoveThisTurn['pro'] = true

  // 先触发主角行动节点（主角第一次主动行动）
  if !cs.nodeTriggered['pro']:
    triggerNode('pro')

  const target = adjacentCell(hero.pos, dir)
  if !canEnter(target):
    // 面向障碍格 → 只转向，不位移
    hero.facing = dir
    return

  hero.facing = dir
  hero.pos = target
  // 队友位置/朝向跟主角同步（但队友自己的行动节点仍然独立存在）

  // 触发残存时间判断
  if anyAliveCharNotUsedSkill():
    startLingeringTimer(1000)
  else:
    phase = 'autoSkills'
```

### 3.3 按 F 跳过

```
trySkip():
  pre: 主角没硬控

  cs.actionCount += 1
  cs.usedMoveThisTurn['pro'] = true     // 规格：跳过也视为一次移动

  // 触发主角行动节点
  if !cs.nodeTriggered['pro']:
    triggerNode('pro')

  // 残存时间判断（同移动）
  if anyAliveCharNotUsedSkill():
    startLingeringTimer(1000)
  else:
    phase = 'autoSkills'
```

### 3.4 连携（E 键）

```
onPressE():
  if !cs.linkActive: return

  const slot = cs.pendingLinks.shift()
  cs.linkActive = false

  // 连携不触发 owner 的行动节点（规格反复强调）
  resolveLinkSkill(slot)

  // 连携释放后继续检查下一个候选
```

### 3.5 逃跑

```
tryFlee():
  pre: 主角正处于玩家操控阶段
  pre: cs.actionCount === 0
  pre: 主角没硬控

  if !cs.nodeTriggered['pro']:
    triggerNode('pro')

  const rate = calcEscapeRate()

  if Math.random() * 100 < rate:
    // 逃跑成功 → 直接退出战斗
    endCombat({ outcome: 'flee' })
  else:
    // 逃跑失败：主角视为跳过 + 失去技能次数
    cs.actionCount += 1
    cs.usedSkillThisTurn['pro'] = true
    // 队友不受影响（队友技能次数保留）
    if anyAliveCharNotUsedSkill():
      startLingeringTimer(1000)
    else:
      phase = 'autoSkills'
```

#### 逃跑概率公式

```
enemy = 主角速度 - max(敌人速度 × 该敌人剩余生命值百分比)（取所有敌人里最大的那一个）
rate = clamp(enemy / 100, 0, 100)（四舍五入保留 1 位小数）
```

多个敌人时，只挑那个"敌人速度 × 剩余 HP%"最大的算。

## 四、碰撞伤害（新机制）

### 4.1 触发规则

**默认且所有敌人都有**，不会在各敌人描述里重复：

> 敌人在移动后，经过了或者恰好停留在主角所在地块时，造成相当于敌人**攻击力 100% 的物理伤害**。每个敌人每回合限 1 次。

触发条件的精确语义：

```
敌人移动路径 = [起点格, 经过格1, 经过格2, ..., 终点格]

for each 敌人的每一步位移:
  if 这一格是主角当前所在地格:
    触发碰撞伤害（如果该敌人本回合还没触发过）

敌人因任何原因原地不动（包括被硬控、目标格不可达算作"原地移动"）:
  如果移动前敌人已经在主角格 → 不触发（移动前不算）
  如果移动后敌人仍然在主角格但本回合没触发过 → 触发
```

### 4.2 重要边界

- **主角和敌人堆叠在同一格** —— 如果双方都没在本回合移动，**不会反复触发碰撞伤害**（因为没移动）
- **"经过"vs"停留"** —— 两者都算，敌人路径上的每一格只要是主角格就触发
- **"移动前已在主角格原地不动"** —— 不算，移动行为本身是触发前提
- **护盾** —— 任何没有特殊说明的"伤害"都可被护盾抵挡，碰撞伤害也一样。主角有护盾时先扣护盾再扣血

### 4.3 伤害结算

```
dealCollisionDamage(enemy, player):
  damage = enemy.atk × 1.0

  // 无特殊说明的伤害一律走护盾优先
  if player.shield > 0:
    absorbed = Math.min(player.shield, damage)
    player.shield -= absorbed
    damage -= absorbed

  if damage > 0:
    player.hp -= damage

  cs.collidedThisTurn[enemy.key] = true   // 标记该敌人本回合已触发过
```

### 4.4 碰撞伤害在敌方回合的触发时机

```
敌方回合（_phaseEnemyTurn）:
  for each enemy in order:
    triggerNode(enemy)
    if 硬控: skip
    else:
      enemyAI(enemy)
        → enemyAI 内部执行敌人移动
        → 每一步位移后检查: 这一格是不是主角格 + 该敌人本回合是否已触发碰撞
        → 满足 → dealCollisionDamage(enemy, player)
```

**每敌人每回合只触发 1 次**（即使它移动路径经过主角格 3 次，也只造成 1 次伤害）。

## 五、行动节点

### 5.1 触发时机

**每个实体独立、无固定先后顺序**。触发条件 = **该实体第一次主动行动的瞬间**（不管这个行动是什么）。

```
可能触发的时刻：
  · 释放主动技能前（owner 是第一次主动行动）
  · 进入 autoSkills 阶段，释放自动技能前（owner 是第一次主动行动）
  · 进入 enemy/summon/neutral 阶段，执行 AI 前（该实体是第一次主动行动）
  · 硬控制单位在回合开始时就触发（先扣冻结/束缚时间，扣到 0 则本回合能行动，否则跳过）

绝对不会触发的时刻：
  · 连携技能（规格反复强调）
  · 纯 UI 操作（切换选中角色等）
```

### 5.2 触发后的原子操作

```
triggerNode(entityKey):
  const ent = cs.entities.find(e => e.key === entityKey)
  if !ent || ent.dead: return
  if cs.nodeTriggered[entityKey]: return     // 本回合已触发过

  // 1. 防御护盾
  ent.shield += ent.displayDef               // 100% 局内防御

  // 2. 扣身上 buff/debuff 持续时间
  for buff in ent.buffs:
    buff.duration -= 1
    if buff.duration <= 0: ent.buffs.remove(buff)
  for debuff in ent.debuffs:
    debuff.duration -= 1
    if debuff.duration <= 0: ent.debuffs.remove(debuff)

  // 3. 扣挂在该实体节点上的结界/境界持续时间
  for zone in cs.zones.filter(z => z.triggerEntityKey === entityKey):
    zone.duration -= 1
    if zone.duration <= 0: cs.zones.remove(zone)

  cs.nodeTriggered[entityKey] = true
```

### 5.3 队友的节点

**队友有独立行动节点**，但队友**没有主动操作**，因此队友的节点通常在：
- autoSkills 阶段（队友的自动技能释放前，若这是队友本回合的第一次主动行动）
- 硬控制时回合开始就触发

队友位置/朝向永远绑定主角，但**节点触发是独立的**，和主角节点谁先触发取决于谁先做第一次主动行动。

### 5.4 硬控制与行动节点的关键时序

```
硬控单位轮到行动时：
  1. 先触发行动节点（节点里扣冻结/束缚的剩余回合数）
  2. 若扣到 0 → 状态消失 → 本次可正常行动
  3. 若没扣到 0 → 本回合跳过全部动作
  4. 节点标记"已触发"（所以本回合不会再触发）

⚠️ 绝对不能反过来写成"先检查硬控、再触发节点"
—— 否则冻结单位永远扣不到持续时间，会被永远冻住。
```

## 六、自动技能阶段（`_phaseAutoSkills`）

```
phase = 'autoSkills':
  for slot in cs.skillGroup.sort(by slot.slot).filter(s => s.kind === 'auto'):
    owner = slot.charKey

    // 四个前置条件
    if slot.cd !== 0: continue
    if !hasValidTargetForSkill(slot): continue
    if cs.hardControl[owner]: continue
    if cs.usedSkillThisTurn[owner]: continue

    // owner 的第一次主动行动 → 触发 owner 节点
    if !cs.nodeTriggered[owner]:
      triggerNode(owner)

    // 主角也是 owner 时（owner==='pro'），也需要触发主角节点
    if owner === 'pro' && !cs.nodeTriggered['pro']:
      triggerNode('pro')

    resolveSkill(slot, owner, source='auto')
    cs.usedSkillThisTurn[owner] = true
    slot.cd = slot.cdDecl || 1

    _checkLinkWindow()    // 每个自动技能后给连携窗口间隙

  phase = 'summons'
```

## 七、敌方回合（`_phaseEnemyTurn`）

```
phase = 'enemy':
  const order = cs.entities.filter(e => !e.dead && e.faction === 'enemy')
                .sort((a, b) => (a.x+a.y) - (b.x+b.y) || a.key.localeCompare(b.key))

  for (const enemy of order):
    triggerNode(enemy.key)       // 先扣冻结/束缚！

    if hasHardControl(enemy):
      log(`${enemy.name} 无法行动。`)
      continue

    enemyAI(enemy)
      → 执行敌人移动（由设计者定义每种敌人的移动逻辑）
      → 每一步位移后检查碰撞伤害（见 §四）
      → 移动附带的攻击效果（大多数敌人没有单独的指向性攻击技能）

  tickAllCooldowns()             // 敌方回合末尾统一扣冷却
  phase = 'roundStart'
```

## 八、元素反应处理栈（可直接复用旧实现）

```
resolveElementReaction(triggerCell, oldElement, newElement, triggerEntity):
  reactionStack = []

  const rxn = REACTION_TABLE[oldElement + '+' + newElement]
  if rxn === undefined:
    triggerCell.attach = newElement
    return

  reactionStack.push(rxn)

  while reactionStack.length > 0:
    const curRxn = reactionStack.pop()
    executeReaction(curRxn, triggerEntity, triggerCell)

    // 反应效果中产生的新附着 → push 进 reactionStack
    for each newAttachCell in curRxn.affectedCells:
      if newAttachCell.attach !== null:
        const nextRxn = REACTION_TABLE[newAttachCell.attach + '+' + curRxn.newAttachElement]
        if nextRxn !== undefined:
          reactionStack.push(nextRxn)

  // 扩散特殊处理（顺时针一圈 + 连锁反应延迟）
  diffusionQueue = executeDiffusionInOrder(startedFromTop=true, clockwise=true)
  for each subEffect in diffusionQueue:
    executeSubEffect(subEffect)
    if subEffect.causedNewReaction:
      reactionStack.push(subEffect.newRxn)

  // 硬性兜底：最多 1 种附着
  for each cell in affectedCells:
    if cell.attach !== null && cell.attach2 !== null:
      cell.attach2 = null
```

## 九、技能释放主流程（`resolveSkill`）

```
resolveSkill(slot, owner, source):
  const sk = getSkillFromSlot(slot)

  // 1. 前置校验（主动技能时 hasValidTarget 已在入口检查过；自动/连携时也各自检查过）

  // 2. 范围计算 —— 严格按主角当前朝向
  const facing = cs.playerFacing          // 主角朝向
  const range = computeSkillRange(sk, owner.pos, facing)

  // 3. 索敌（三条铁律，见 02-核心概念 §6.1）
  const attachCells = filterByRule(range, rule='attachment')
  const targetEntities = filterByRule(range, rule='damage')
  // ⚠️ targetEntities 可能包含多个同格堆叠的实体，全部命中（按阵营过滤）

  // 4. 对 attachCells 施加元素附着
  if (sk.element):
    for each cell in attachCells:
      applyAura(cell, sk.element, owner)
      // applyAura 内部：若已有附着 → 触发 resolveElementReaction → 清空 cell.attach

  // 5. 对 targetEntities 造成伤害
  if (sk.element):
    for each ent in targetEntities:
      dealElementalAttrDamage(ent, sk.element, mult, owner)

  if (sk.type === 'physical'):
    for each ent in targetEntities:
      dealPhysicalDamage(ent, mult, owner)

  // 6. selfEffects / allyEffects buff 施加
  for each effect in sk.selfEffects:
    applyBuff(effect, owner)
  for each effect in sk.allyEffects:
    for each ally in allies:
      applyBuff(effect, ally)

  // 7. 胜负条件检查（最末尾必须调用）
  checkBattleEndConditions()
```

### 9.1 多实体堆叠下的索敌

当 `targetEntities` 中包含**同一格子上多个堆叠的实体**时：
- **全部命中**（按阵营规则过滤后）
- 伤害结算按原阵营/防御/护盾规则分别对每个实体处理
- 元素附着施加在**该格的地块上**（不是给某个实体）

## 十、结束战斗

```
endCombat({ outcome }):
  cs.ended = true

  switch outcome:
    case 'victory':
      grantCombatReward(cs.enemies)
      break
    case 'defeat':
      deductHealthByEnemyType(cs.enemies)
      if G.hero.health <= 0:
        globalGameOver()          // 健康归零 → 全局失败
        return
      break
    case 'flee':
      break

  // === 清理 ===
  // 1. 移除非主角新生成的实体（召唤物、敌方新生成的等；特殊说明除外）
  G.map.cells[*].entities = cell.entities.filter(e => e.key === 'pro' || e.isPersistent)

  // 2. 元素附着**保留**（不清空，到下一日新地图生成时统一清除）
  // 3. 还原主角位置朝向
  G.px = cs.startPos.x
  G.py = cs.startPos.y
  G.hero.facing = cs.startFacing

  // === UI 切回探索模式 ===
  combatState = null
  switchMode('explore')
  renderMap()                      // 地块 content 图标恢复显示
  refreshHUD()
```

## 十一、优先级总表（任何冲突按此从上到下裁决）

| 序号 | 优先级 | 来源 | 具体内容 |
|---|---|---|---|
| 1 | 最高 | 胜负条件 | 敌方全灭 / 主角死 / 健康 0 → 立即退出 |
| 2 | 极高 | 元素反应 | 游戏内最高优先级，任何动作立即暂停，处理到空栈后恢复 |
| 3 | 高 | 连携技能 | 可打断当前正在进行的动作 |
| 4 | 中 | 自动技能队列 | 顺序执行，每个间隙给连携窗口 |
| 5 | 低 | 正常行动 | 玩家操控、召唤物 AI、中立 AI、敌方 AI |
| 6 | 碰撞伤害 | 敌方 AI 执行中 | 敌方 AI 内部每步移动后检测，不单独插队 |

## 十四、战斗关卡数据（具体作战配置）

> 敌人不会单独出现。一场作战就像一个关卡，出现哪些敌人由设计者单独配置。本项目先给出 **2 种具体的战斗类型**（作战 / 紧急作战），方便写代码。以后可以添加更多类型。
>
> 敌人的基础数据、天赋、技能详见 [05-角色·技能·物品 §八](05-角色·技能·物品.md)。

### 14.1 关卡通用规则

| 项 | 说明 |
|---|---|
| 敌人进攻点生成 | 每场战斗开始时，按关卡配置生成固定数量的敌人进攻点（`isEnemySpawnPoint: true`），生成规则见 [03-战斗系统 §一·一](03-战斗系统.md) |
| 敌人回合生成 | 前 3 个回合，每回合从进攻点生成本回合敌人。之后回合不再生成新敌人 |
| 史莱姆选择 | 每次生成时，从 7 种元素史莱姆中**随机独立判定**（不保证不重复，多只同元素史莱姆完全可能） |
| 战败健康减少 | 战斗关卡定义。**不是史莱姆个体属性**，是战斗失败这个事件本身扣健康 |
| 战斗奖励 | 战斗关卡定义，胜利时结算 |

### 14.2 关卡一：史莱姆时间（作战）

| 项 | 值 |
|---|---|
| `content.type` | `'battle'` |
| 敌人进攻点数 | 1 个 |
| 敌人生成 | 前 3 个回合，每回合从 7 种史莱姆中随机生成 1 只 |
| 战斗奖励 | 果子 * 3；属性升级随机二选一（主角攻击力 +1 / 主角最大生命值 +5） |
| 战败健康减少 | 1 |
| 备注 | 最常见的普通作战 |

### 14.3 关卡二：史莱姆暴走！（紧急作战）

| 项 | 值 |
|---|---|
| `content.type` | `'emergency'` |
| 敌人进攻点数 | 3 个（生成时优先避免重叠，即进攻点坐标互不相同；若地图太小无法避免则允许） |
| 敌人生成 | 前 3 个回合，每回合从 7 种史莱姆中随机生成 1 只 |
| 战斗奖励 | 果子 * 3、木材 * 1、亚麻 * 1；属性升级随机三选一 |
| 战败健康减少 | 1 |
| 备注 | 紧急作战比普通作战更难（多了 2 个敌人进攻点），奖励也更丰厚 |
