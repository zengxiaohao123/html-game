> 本文档是整套规格的**导航 + 速查表**，用于 AI / 新贡献者快速定位该去读哪份文档、哪些是"红线不能碰"的约束。修改任何代码前必须先读对应章节。

## 一、阅读顺序

```
新贡献者 / AI agent 进入项目：
  → 先读 01-总览.md（项目是什么、代码结构、四种模式）
  → 再读 02-核心概念.md（全部术语的权威定义，代码注释里出现的概念都在这里）
  → 进入要修改的具体模块：
      · 改战斗相关（战斗流程、元素反应、技能释放、AI、行动节点） → 03-战斗系统.md
      · 改探索/地图/载具/空地搜索 → 04-探索与地图.md
      · 改角色数值/技能数据/物品数据/技能组逻辑 → 05-角色·技能·物品.md
      · 改 UI 布局/交互/快捷键/角色技能区 → 06-UI·交互.md
  
修改后 / 新增内容涉及的规格点必须同步更新对应文档（本文档除外）。
```

## 二、红线（绝对不能违反）

以下是**规格里用"必须""绝对""一律"强约束的条目**，任何修改若触碰这些点必须先在文档里更新规格再动代码：

| 红线 | 位置 | 说明 |
|---|---|---|
| **元素附着只在地块上** | 02-核心概念 · 元素附着 | 实体永远不会被附着。代码里所有给实体 setAura 的旧代码（比如 `enemy.aura = 'fire'`）都是**必须删除的历史残留** |
| **7 种元素都可以附着** | 02-核心概念 · 元素附着 | 风、岩、冰、雷、水、火、草——全部可以。旧代码里 `AURA_ELEMS` 排除风岩的硬编码是**必须删除的错误** |
| **索敌严格按三条规则** | 02-核心概念 · 索敌规则 | 技能描述文本里的关键词已经编码了索敌逻辑，代码里按 `ruleTag` 分支。**绝对不能**默认"只打敌人"而不处理"所有可攻击实体"或"严格按描述筛选"两种情况 |
| **自动技能不能被玩家手动触发** | 02-核心概念 · 技能分类 | UI 层、逻辑层、快捷键层三道屏障 |
| **连携不触发行动节点** | 03-战斗系统 · 行动节点 | 规格明确。代码里 `resolveLink()` 不能 call `triggerNode()` |
| **战斗中不能用消耗品** | 05-角色·技能·物品 · 消耗品 | 战斗中打不开背包。规格没写"战斗中急救包"就默认不能用 |
| **角色页面不能调技能组** | 05-角色·技能·物品 · 技能组 | 技能组调整**唯一入口**是编队界面（iconbar 编队按钮） |
| **战斗中的信息选项区 ≠ 技能描述区** | 06-UI·交互 · 信息选项区 | 信息选项区（#promptZone）战斗时只显示地块 + 单位详细信息。技能描述在底部角色技能区的右侧面板（独立 DOM）。这两个区域**职责完全不同** |
| **行动节点 = 先扣持续时间再检查硬控** | 02-核心概念 · 硬控制时序 | 冻结单位的节点触发顺序不能反。反了 = 永远冻住 |
| **元素反应 = 游戏内最高优先级** | 02-核心概念 · 元素反应 | 任何正在进行的动作（伤害、附着、敌方 AI、连携、自动技能队列、扩散剩余圈）碰到反应都要立即暂停、处理完反应栈再恢复 |
| **扩散 = 先处理完一圈再处理连锁** | 02-核心概念 · 扩散反应 | 扩散的连锁反应延迟处理——扩散范围内每个地块的反应先记录，一圈做完后再按记录顺序处理 |
| **永久物品不可出售** | 05-角色·技能·物品 · 永久物品 | 代码里永久物品 `sellable` 必须硬编码 false |
| **队友不会死亡、没有生命值** | 02-核心概念 · 阵营 | 队友状态永远是活着。UI 里永远不显示队友 HP 条（战斗里队友 HP 条是旧规格残留，应删除） |
| **徒步跋涉 / 疾行严格不属于载具** | 04-探索与地图 · 载具定义 | 任务「便捷出行」的 6 次计数只算真正的载具。代码里有 `isActuallyVehicle(k) = k!=='walk' && k!=='dash'` 判断 |

## 五、修改流程建议

1. **改动触发**：
   - 修复 bug → 定位功能点 → 查文档 → 代码里找到入口 → 按规格修
   - 新增功能 → 先补文档（本文档或对应章节）→ 再写代码
   - 规格歧义 → 必须先和产品 owner 确认（当前就是你本人）→ 再写代码

2. **写入代码前**：
   - 查 `docs/03-战斗系统.md` §十一 或 §四 有没有差异清单项
   - 查 `docs/06-UI·交互.md` §八 有没有差异清单项
   - 若清单里有 → 直接按"规格"列的正确状态写代码
   - 若清单里没有 → 说明规格里没明说 → **需要先和 owner 确认**

3. **写入代码后**：
   - 本文档 §四 差异清单里若是新增的差异项 → 更新进去
   - 若是已修复的差异项 → 在"当前代码"列标注"已修复"
   - 若是新增功能 → 对应章节补上规格描述（不是只改代码不改文档）

## 六、本项目的文档纪律

- **docs/*.md 是唯一规格来源**。代码注释、旧文档、旧 commit 里的规格**全部失效**。
- **docs/js/*.js** 是"代码注释快照"—— 仅用于 AI 搜索 `data.js` 里某个技能数据时快速定位，不是规格。
- **AGENT_CONTEXT.md 已删除**—— 它承担的信息已拆分进 01/02/03/04/05/06/07。
- **docs/archive/ 已删除**—— 里面全是旧规格（09-03/09-02 时代的），与新规格冲突，保留会污染认知。
- **docs/battle-spec.md 已删除**—— 它的权威内容已完整迁移进 02/03。
- **index.html、js/*.js、style.css 里的注释可以提到"规格"但必须引用正确章节；若注释与新规格冲突 → 改注释**（不是改规格）。
