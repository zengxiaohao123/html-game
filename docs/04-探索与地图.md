# 04 · 探索与地图

> 阅读前置：[02-核心概念](02-核心概念.md)（地块、载具、行动力、回字形地图等术语定义）。
> 本文档是**探索与地图机制唯一规格来源**。

---

## 一、地图生成

### 1.1 地图参数

- 尺寸：**矩形**，`width`（宽）和 `height`（高）分离存储，不强求相等
- 坐标：`(x, y)`，左上角为 `(0, 0)`，`x` 范围 `[0, width-1]`，`y` 范围 `[0, height-1]`
- 默认值：**3×3**，固定不变，不受每日随机波动影响
- 改变地图尺寸的唯一途径：**特定道具或特殊剧情地图**（具体改动时机和数值由设计者另行指定）

### 1.2 回字形结构

每日新地图生成时，**外圈 + 内部 void 是默认结构**：

```
回字形判定逻辑：
  对于任意地块 (x, y)：
    如果 x === 0 或 y === 0 或 x === width-1 或 y === height-1 → 外圈（可通行区域）
    否则 → 内部（默认 terrain = 'void'，不可通行、不可附着、不受任何效果影响）
```

**特殊说明**：
- 四个角上的格子（如 3×3 的 (0,0)、(0,2)、(2,0)、(2,2)）**没有特殊规则**，默认可停留、可通行，和其他外圈格子完全一样
- 地块本身没有区别，回字形只是**默认生成规则**，不是地块的固有属性
- 特殊剧情/道具可以把内部 `void` 改成可通行地形（此时该格等同于外圈格子，无任何特殊限制）

### 1.3 地图生成时机与流程

**时机**：每天睡觉进入下一天时，一次性生成新地图（day=0 不生成地图，day=1 才是第一张）

**流程**：

```
generateMap(day, opts):
  1. 确定 width / height（默认固定值；道具/特殊地图时用 opts 指定值）
  2. 初始化所有格子的 terrain：
     · 外圈：根据具体地形设计生成（地形设计待设计者给出）
     · 内部：全部 terrain = 'void'
  3. 地块内容 content 一次性生成（具体概率待设计者给出）：
     · 只在外圈可通行地块上分布（内部 void 格不生成 content）
     · 不同类型有不同的固定概率，不固定数量
     · 空地 content.type = 'empty' 不显示图标（空地无图标）
     · 其他类型有各自的图标（玩家可看到图标但看不到具体事件/敌人内容）
  4. 主角出生位置：
     · 优先：沿用上一天睡觉时的位置（如果该位置在新地图上仍然合法可进入）
     · 回退：如果地图变小 / 位置越界 / 特殊地图等原因 → 随机选一个合法可进入位置
  5. 记录主角朝向（继承上一天，或默认 'up'）
  6. 返回完整地图对象
```

### 1.4 地图上地块的完整字段

```
Cell {
  x, y,                    // 坐标
  terrain,                 // 地形（由设计者定义，细分；只有 void 是不可通行）
  content: {               // 地块内容
    type,                  // 'empty' | 'battle' | 'emergency' | 'event' | 'loot' | 'reward'
    done?                  // 是否已被进入（部分内容进入后标记）
  } | null,
  attach,                  // 元素附着（null 或 7 种元素之一；探索中不会被玩家修改）
  entities: Entity[],      // 本格上的实体列表（可叠放无限多个；UI 每 2 秒循环切换图标）
  isEnemySpawnPoint?       // 战斗态专用：敌人进攻点标记
}
```

**注意**：旧规格里每格 `entityId` 只能放 1 个实体。新规格改为 `entities: Entity[]` 可叠放无限多个。

### 1.5 元素附着的生成与清除

- **新地图生成时**：所有地块元素附着统一清空（战斗中残留的附着在这里被清掉）
- **探索模式中**：**玩家无法使用任何技能（天赋除外）**，无法添加或清除元素附着
- **战斗中生成的附着**：按战斗规则正常结算，战斗结束后**保留**到下一日新地图生成时才统一清除

### 1.6 探索模式下的"内容在地图上显示"规则

- 探索时，`content.type` 以**图标**显示在地块上，玩家可看到是什么类型但看不到具体内容
- 战斗开始时，**所有 content 图标暂时隐藏**
- 战斗结束后，**content 图标重新可见**（已被进入过的地块 content.type 会自动变为 'empty'）
- `empty` 类型不显示图标
### 1.7 回字形外圈的顺时针 / 逆时针方向约定

坐标系统：左上角为 `(0, 0)`，向右 `x` 递增，向下 `y` 递增（常规屏幕坐标）。

**顺时针**：沿回字形外圈走一圈的固定方向，顺序为 `(0, 0) -> (0, 1) -> (0, 2) -> ... -> (0, height-1) -> (1, height-1) -> (2, height-1) -> ... -> (width-1, height-1) -> (width-1, height-2) -> ... -> (width-1, 0) -> (width-2, 0) -> ... -> (0, 0)`。

**逆时针**：完全相反的方向，即顺时针环的反向。

代码实现时，顺时针 / 逆时针本质上是把回字形外圈当作一条**闭合环路**来理解。只要当前位置在外圈上，它的顺时针下一步就是固定的一个格子，不需要每一步重新做方向判定。

备注：此前曾有误解把回字形当作"底边先向右"，实际以本节定义为准。

## 二、探索移动

### 2.1 移动方式

主角每次只能沿**上下左右**方向移动 1 格。**两种操作等价**：

- **WASD 键**：按下方向键立即移动
- **鼠标点击**：先点击目标地块 → 再点击「前往」按钮

**原地踏步**：点击自己当前所在格 → 点击「前往」。视为"再次进入本地块"，消耗 1 行动力。

### 2.2 移动消耗

```
每次移动（含原地踏步）消耗：
  · 行动力：固定 1 点（与方向、载具无关）
  · 载具次数：按当前选中载具规则消耗（见载具章节）
  · 主角朝向：更新为移动方向
  · 队友位置/朝向：同步主角
```

### 2.3 玩家无法控制的事

探索模式中，玩家**不能**：

- 使用任何主动技能、自动技能、连携技能（**天赋除外**，天赋在编队时就全场景永久生效）
- 对地块添加元素附着
- 主动清除地块上的元素附着

### 2.4 移动触发内容逻辑（伪代码）

```
moveExplore(x, y):
  1. 检查是否处于战斗态 / 事件态 / 剧情态 → 是则拒绝移动
  2. 检查行动力（actionPoint >= 1） → 不足则拒绝移动
  3. 检查目标格是否可进入（passable(x, y)） → 不可进入则只转向，不位移
  4. 消耗行动力：G.hero.actionPoint -= 1
  5. 消耗载具次数
  6. 更新主角朝向、坐标；队友同步
  7. 读取 target.content.type：
     switch(ct):
       'battle' / 'emergency' / 'reward':
         startCombat(target)                // 进入战斗
       'loot' && !target.content.done:
         openLoot(target)                   // 拾取 → done=true → type 自动改 'empty'
       'event' && !target.content.done:
         startEvent(x, y)                   // 进入剧情 → done=true → type 自动改 'empty'
       'empty':
         searchEmpty()                      // 空地搜索
       兜底:
         log('这里没有什么特别的。')
  8. refreshHUD() + renderMap()
  9. 触发主线剧情检查
```

### 2.5 空地搜索（`searchEmpty()`）

玩家进入 `empty` 地块或原地踏步时触发，具体资源池、抽取概率、补偿机制等由设计者另行定义，保持原有"空地搜索消耗 1 行动力"的语义。

## 三、地块预览（点击地块 → 点前往之前）

点击地块（还没点「前往」按钮）时，信息选项区显示：

```
位置 (x+1, y+1)
地形：[具体地形名称]
地块内容：空地 / 有战斗 / 有事件 / 有战利品（已被拾取）/ 不可通行
```

同时 `#goBtn` 按钮更新为：
- 不可前往 → 按钮禁用，文字 "无法前往"
- 可前往 → 按钮启用，文字 "前往 · 消耗 1 行动力 + N 载具次数"

## 四、载具规则

载具机制保留原有设计，以下只列核心规则：

| 要点 | 说明 |
|---|---|
| 徒步跋涉 / 疾行 | 不算狭义载具，但放在载具页面；infinite:true 永不耗尽 |
| 载具页面 | iconbar 入口，可切换载具 |
| 载具消耗 | 每次移动 / 原地踏步消耗 1 次；耗尽自动切回徒步 |
| 战斗中 | 移动和按 F 跳过都消耗 1 次载具 uses |
| uses 是否恢复 | 规格未明说，默认不恢复 |

**原地踏步也消耗载具**：玩家站在 A 格点「前往 A 格」 → 完整消耗逻辑（行动力 + 载具次数 + 朝向重算 + 地块内容重新触发）。

## 五、睡觉进入下一天

iconbar「睡觉」按钮，核心行为：

- 生成全新地图（旧地图完全丢弃）
- **所有地块元素附着统一清除**
- 行动力回满
- 永久物品/天赋在睡觉时各自触发效果（被子回血、陷阱收获、好人卡金币、陆悠悠巧手……）
- 心理健康判定 / 抑郁判定（psyStress 相关）
- 主线剧情检查

睡觉后自动切到新地图、刷新 HUD、保存存档。

## 六、主线剧情触发

探索每一步移动 / 事件 / 战斗结算 / 睡觉 之后，都会调用 `triggerMainStorySeg()` 检查是否应该推进主线。
- 主线剧情分若干段落（segment），每个段落有触发条件
- 条件满足 → 自动切到剧情模式 → 打字机显示剧情文字 → 最后一页结束后可能有选项
- 段落完成后 `mainStorySeg += 1`

## 七、进入战斗后的地块处理

### 7.1 战斗开始瞬间

1. **隐藏所有地块的 content 图标**（UI 上隐藏，数据层保留，战斗结束后恢复）
2. **地图上随机选一个合法格子作为敌人进攻点**（具体选格规则见 03-战斗系统 §一）
3. 从进攻点生成战斗配置的初始敌人（默认每回合生成 1 个，特殊说明时可一次生成多个）
4. 记录主角开战时的位置和朝向（战斗结束时还原用）

### 7.2 战斗中的地图显示

战斗中地图上显示：
- 地形（同探索）
- 主角头像（+ 朝向箭头）
- 敌人头像（每格叠放多个实体时**每 2 秒循环切换图标**）
- 地块元素附着标记
- 敌人进攻点标记（待图标素材）
- 结界范围标记（透明底色）

### 7.3 战斗结束后（胜利 / 战败 / 逃跑）

1. **移除非主角新生成的实体**（战斗过程中产生的召唤物、新敌等，特殊说明的除外）
2. **战斗中生成的元素附着保留**（不清除）
3. **主角强制传送回开战前的位置和朝向**（快照还原）
4. **地块 content 图标重新可见**
5. 如果战斗胜利 / 事件完成 / 战利品已拾取 → 对应格子 `content.type` 自动改为 'empty'

---

## 八、战斗中载具的处理

- 战斗中当前选中载具会被快照保存
- 战斗中**载具消耗 uses**：每次移动消耗 1 次；按 F 跳过（原地踏步语义）也消耗 1 次（规格明确）
- 载具消耗是永久的，战斗结束时**不还原 uses**（快照里记录 uses 只是为了知道战斗开始时是多少，不是为了恢复）
