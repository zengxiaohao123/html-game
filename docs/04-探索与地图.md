## 一、地图生成

### 1.1 地图参数

- 尺寸：正方形，边长固定（具体值由 `generateMap()` 决定）
- 坐标：`(x, y)`，左上角为 `(0, 0)`
- 每个地块：`{ terrain, content, attach, entityId }`

### 1.2 地形生成（`terrain`）

| 地形类型 | 生成概率 | 可通行 | 备注 |
|---|---|---|---|
| `void`（外部地块） | 外圈一圈 | ❌ | 地图边界，规格明确"不可进入、不可附着、不可受效果影响" |
| `obstacle`（山脉） | ~10-15% | ❌ | 内部障碍，不可通行。有视觉 icon |
| `water`（水域） | ~5-10% | ✅（减速） | 可通行但某些载具不能走（如地龙不会游泳） |
| `ice`（冰面） | ~3-5% | ✅（打滑） | 踩到时有概率多走 1 格 |
| `grass`（草地） | ~20% | ✅ | 视觉绿色；踩到 + 草附着时会触发燃烧反应 |
| `normal`（普通） | 其余 | ✅ | 默认可通行地块 |

### 1.3 地块内容生成（`content`）

生成策略：
1. **先在外圈 void 确定好**
2. 在内部可通行地块中**随机分布** `battle / emergency / event / loot / reward`
3. 剩余的所有可通行地块 content 默认都是 `empty`
4. 进入战斗、事件、奖励后 content 会被标记 done 或改为 empty（由各流程处理）

### 1.4 主角出生位置

固定在某一个内容为 `empty`、地形为 `normal`、不靠近任何 obstacle 的格子上（避免刚出生就卡住）。

### 1.5 探索模式下的"内容在地图上显示"规则

探索时，`content.type` 会以**图标**显示在地块上：
- `battle`：红色剑图标
- `emergency`：红底感叹号图标
- `event`：黄色对话图标
- `loot`：宝箱图标
- `reward`：Boss 图标（大号）
- `empty`：不显示图标（空地）

进入战斗后，**所有 content 图标暂时隐藏**；战斗结束后如果该地块还没被进入过，图标恢复显示。

## 二、地块预览（点击地块 → 点前往之前）

点击地块时（还没点"前往"按钮），信息选项区显示：

```
位置 (x+1, y+1)
地形：山脉 / 水域 / …
地块内容：空地 / 有战斗 / 有事件（未完成） / 有战利品（已被拾取） / 不可通行

（如果该格已处于战斗态：显示 "这里曾发生过战斗，如今已是空地。"）
```

同时 #goBtn 按钮更新为：
- 不可前往 → 按钮禁用，文字 "无法前往"
- 可前往 → 按钮启用，文字 "前往 · 消耗 N 行动力（徒步）" / "前往 · 距离 3（疾行）" / "前往 · 载具次数剩余 N（扫帚）"

## 三、移动（载具规则）

### 3.1 载具定义总表

| key | 名字 | 载具？（狭义） | 使用方式 | 行动力消耗 | 战斗中能用 |
|---|---|---|---|---|---|
| `walk` | 徒步跋涉 | ❌ 普通移动方式 | WASD 相邻 1 格 | 固定 1 | ✅（一次移动算载具消耗） |
| `dash` | 疾行 | ❌ 普通移动方式 | 点目标格 → 前往 | 曼哈顿距离 | ❌（exploreOnly） |
| `dragon` | 地龙 | ✅ 载具 | 直线 2 格 | 固定 1 | ✅ |
| `mushroom` | 蘑菇弹 | ✅ 载具 | 传送至目标格 | 0 | ❌ |
| `carriage` | 马车 | ✅ 载具 | 直线 3 格 | 固定 1 | ✅ |
| `broom` | 魔法扫帚 | ✅ 载具 | 直线 3 格 | 固定 1 | ✅ |
| `carpet` | 魔法飞毯 | ✅ 载具 | 任意格 | 固定 1 | ❌ |
| `qiaoyu` | 巧遇 | ✅ 载具 | 任意格（每日限 1 次） | 固定 1 | ❌ |

**徒步跋涉、疾行** 严格不算载具（虽然放在 VEHICLES 表里方便代码复用）。代码里 `isActuallyVehicle(key) = key !== 'walk' && key !== 'dash'` 作为判断条件。

### 3.2 载具页面

iconbar 「载具」按钮打开载具选择模态。内容：
- 每一行一个载具：名字、icon、当前剩余次数（或无限）、使用方式说明
- 当前选中载具：高亮显示
- 切换载具：点一行即切换

**徒步跋涉、疾行** 放在载具页面最上方（因为最常用），不是载具但放在这里方便玩家选择。

### 3.3 载具消耗规则

```
consumeVehicleForMove():
  const v = getSelVehicle()
  if (v.infinite) return        // walk / dash：永远无限
  v.uses -= 1
  if (v.uses <= 0):
    // 次数耗尽 → 自动切回徒步跋涉
    vehicleSel = indexOfKey('walk')
    log(`载具【${v.name}】使用次数耗尽，已自动切换回徒步跋涉。`)
```

**原地踏步也要消耗载具**：玩家站在 A 格点"前往 A 格" → 按当前载具规则走完整消耗逻辑（行动力 + 载具次数 + 主角朝向重算 + 行动计数 + 地块内容重新触发）。

## 四、进入地块时的内容触发逻辑

`moveExplore(x, y, cost)` 内部（简化伪代码）：

```
moveExplore(x, y, cost):
  1. 检查战斗态、事件态 → 都不能移动
  2. 计算 moveCostFor(x, y)（按当前载具）
     不可达 → 返回
     行动力不足 → 返回
  3. G.hero.actionPoint -= cost
  4. consumeVehicleForMove()
  5. 重算朝向 dirToFacing(dx, dy)
  6. 坐标更新 G.px = x, G.py = y
  7. 队友位置/朝向同步主角
  8. 触发相关永久物品效果：
     · 蹁跹（陆悠悠）→ 移动后回血 hv
     · 枯木新枝（永久物品）→ 每次移动 +12 HP × 叠加数
  9. 读取 target.content.type：
     switch(ct):
       'battle' / 'emergency' / 'reward':
         startCombat(target)
       'loot' && !target.content.done:
         openLoot(target)         // 拾取，done=true，type自动改 'empty'
       'event' && !target.content.done:
         startEvent(x, y)        // 进入剧情，done=true，type自动改 'empty'
       'empty':
         searchEmpty()           // 空地搜索（下面详细）
       兜底:
         log('这里没有什么特别的。')
  10. refreshHUD() + renderMap()
  11. 触发主线剧情 check（triggerMainStorySeg）
```

### 4.1 空地搜索（`searchEmpty()`）

```
searchEmpty():
  // 选资源池
  pool = (G.region === 'wild') ? NATURAL_RESOURCES : CITY_RESOURCES
  items = {}
  
  // 尝试最多 3 次抽取：每次 50% 概率拿到 2 个
  found = false
  for i in range(3):
    if Math.random() < 0.5:
      kind = pool随机
      items[kind] = (items[kind] || 0) + 2
      found = true
    else:
      break
  
  if found:
    // 加到背包
    for k in items: G.inventory[k] = (G.inventory[k]||0) + items[k]
    return items描述
  
  // 没找到 → 判定《愧怍》补偿
  kuiZuoN = G.inventory.kuiZuo || 0
  if kuiZuoN > 0:
    report = []
    for i in range(kuiZuoN):
      r = Math.random()
      if r < 0.5: continue                    // 50% 不获得
      kind = pool随机
      if r < 0.75: G.inventory[kind] += 1     // 25% ×1；加起来 75%
      else:        G.inventory[kind] += 2     // 25% ×2
    if report.length > 0:
      return '(《愧怍》)'  // 特殊标记
  
  return null   // 真·空手而归
```

### 4.2 原地踏步

```
原地踏步 = 触发条件：点自己所在格 → 点前往

消耗：
  · 行动力：1 点（与载具无关，规格固定）
  · 载具次数：1 次（当前选中的载具）
  · 主角行动计数 +1（探索时不显示行动计数，但内部状态机里"进入战斗后"这个计数会被带入）
触发的地块内容：
  · 重新走一遍 enterCell 分支 → 如果该格 content.type 是 'empty' → 再次触发 searchEmpty()
  · （允许反复进空地格反复搜索）
```

### 4.3 多次进入同一地块

**允许。** 空地格可以反复搜（每次离开回来都有机会搜到东西）。战利品格/事件格完成后 `type` 改为 `empty`，下次进入也会触发空地搜索。

## 五、进入战斗后的地块处理

### 5.1 战斗开始瞬间

所有地块的 `content` 字段**隐藏**（UI 上不显示图标），content 的效果**暂时失效**。进入战斗的地块上会生成敌方单位（`startCombat(target)` 内部逻辑）。

### 5.2 战斗中的地块状态

战斗中地图上显示：
- 地形（同探索）
- 主角头像（+ 朝向箭头）
- 敌人头像（+ 朝向箭头 + HP 条）
- 地块元素附着标记（颜色小标签，7 种不同色）
- 结界范围标记（透明底色）

### 5.3 战斗结束后

- 主角回到进入点（快照还原）
- 还原朝向（快照还原）
- 地块 content **重新可见**（**除非**这个格子在进入战斗前已经有 done=true 的标记——那会一直保留 empty 状态）
- 地块元素附着：战斗中产生的附着按规则保留到下一日

---

## 六、战斗中载具的处理

- 战斗中当前选中载具会被快照保存（`combatState.vehicles[]`）
- 战斗中**载具消耗 uses**：
  - 每次移动 → 消耗 1 次
  - 按 F 跳过（原地踏步语义） → 消耗 1 次（规格明确）
  - 徒步跋涉/疾行 infinite:true 所以永远不会真耗尽，行为上和"不消耗"等价
- 战斗快照会在战斗结束时还原载具 uses（避免战斗中消耗掉了影响探索）—— 但如果规格决定"战斗中的载具消耗是永久的"，需要改 save.js 的快照还原逻辑

---

## 七、主线剧情触发

探索每一步移动 / 事件 / 战斗结算 / 睡觉 之后，都会调用 `triggerMainStorySeg()` 检查是否应该推进主线。

- 主线剧情分若干"段落"（segment），每个段落有触发条件
- 条件满足 → 自动切到剧情模式 → 打字机显示剧情文字 → 最后一页结束后可能有选项
- 段落完成后 `mainStorySeg += 1`，下一段剧情的触发条件会重新检查

---

## 八、睡觉

iconbar 「睡觉」按钮：
- 立即回满主角 HP
- 永久物品触发效果（goodCard 每天 +1 金币、deadwoodSprout 每天回血、windChime 每天聊天成功率+2%……）
- **下一日**生成全新地图（旧地图丢弃）
- 下一日开始时，所有战斗中残留的地块元素附着**统一清除**
- 载具 uses 是否恢复（规格没明说，默认不恢复；要恢复需永久物品触发）

睡觉后自动切到新地图、刷新 HUD、保存存档。
